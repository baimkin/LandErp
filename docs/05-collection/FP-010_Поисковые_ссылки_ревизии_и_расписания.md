# FP-010 — Поисковые ссылки, ревизии и расписания

**Версия:** 0.1  
**Статус:** Черновик  
**Владелец:** администратор сбора / владелец продукта  
**Модуль-владелец:** Administration  
**Зависимости:** ADR-001, FP-001, FP-002, FP-003  
**Блокирует:** FP-011, FP-012 и первый сквозной сбор

## 1. Решение

Администратор вручную создаёт поисковую конфигурацию из готовой URL-ссылки Авито,
даёт ей понятное название, выбирает источник, расписание, временную зону,
приоритет и безопасные лимиты. Значимое изменение конфигурации создаёт неизменяемую
ревизию. Каждый SearchRun и CollectionTask ссылается на конкретную ревизию, поэтому
можно доказать, что и с какими настройками запускалось.

## 2. Ценность и результат

- 30–50 поисков управляются в одном интерфейсе.
- URL и расписание не зашиты в Agent.
- Администратор может остановить один поиск без остановки системы.
- Изменение URL не меняет смысл уже выполненных запусков.
- Ручной запуск работает до автоматического расписания.
- Ошибка конфигурации видна до выдачи задания Agent.

## 3. Границы

### Входит

- CRUD поисковой конфигурации с архивированием вместо физического удаления;
- источник `Avito` как первое допустимое значение;
- понятное название и описание территории;
- URL и безопасная нормализация;
- неизменяемые SearchRevision;
- ручной запуск;
- группы расписаний и индивидуальное переопределение;
- временная зона бизнеса;
- приоритет, лимит страниц, длительности и повторов;
- pause/resume;
- аудит и история изменений;
- UI списка и карточки поиска;
- проверка пересечений и предупреждение о возможных дублях поиска.

### Не входит

- автоматический конструктор фильтров площадки;
- открытие браузера и парсинг;
- очередь и аренда задания;
- точная геометрия области поиска;
- автоматическое объединение похожих поисков;
- второй источник;
- автоматическая смена URL при изменении площадки.

## 4. Роли и права

| Действие | Разрешение |
|---|---|
| Просмотр | `searches.read` |
| Создание и изменение | `searches.manage` |
| Pause/resume | `searches.manage` |
| Ручной запуск | `searches.run` |
| Просмотр истории и аудита | `searches.read`, при расширенном аудите `audit.read` |

Manager может получить `searches.read`, но не обязан управлять расписанием.

## 5. Термины

| Термин | Значение |
|---|---|
| SearchDefinition | Стабильная бизнес-идентичность поиска |
| SearchRevision | Неизменяемая версия URL и параметров исполнения |
| ScheduleGroup | Переиспользуемое временное правило запуска |
| SearchScheduleOverride | Индивидуальное отличие конкретного поиска |
| SearchRunRequest | Намерение запустить конкретную ревизию вручную или по расписанию |
| Pause | Запрет создавать новые запуски при сохранении истории |
| Archive | Удаление из рабочего списка без потери ссылок истории |

## 6. Основные сценарии

### 6.1. Создание поиска

1. Администратор выбирает источник Авито.
2. Вставляет готовый URL и вводит название, например «Пушкино — ИЖС».
3. Выбирает группу расписания и лимиты.
4. Сервер нормализует URL только по утверждённым правилам и валидирует домен/схему.
5. Создаются SearchDefinition и Revision 1.
6. В аудит записывается автор и безопасный набор параметров.

### 6.2. Изменение

1. Администратор открывает текущую конфигурацию.
2. Меняет URL, лимит или другой значимый параметр.
3. Сервер проверяет optimistic concurrency.
4. Создаётся новая ревизия; старая остаётся неизменной.
5. Следующий запуск использует новую активную ревизию.

Изменение только отображаемого названия SearchDefinition может не создавать
ревизию, если оно не влияет на исполнение.

### 6.3. Ручной запуск

1. Сервер проверяет `searches.run`.
2. Фиксирует активную ревизию на момент команды.
3. Не создаёт второй активный запуск той же ревизии, если параллельность запрещена.
4. Передаёт запрос в Collection через публичный контракт.
5. UI показывает созданный SearchRun ID и состояние.

### 6.4. Pause

Pause не отменяет уже исполняемое задание без отдельного действия. Он запрещает
создание новых запусков. UI явно показывает разницу между pause поиска и аварийной
остановкой источника.

## 7. Данные

### SearchDefinition

- `Id` UUIDv7;
- `OrganizationId`;
- `SourceCode`;
- `Name`;
- `LocationLabel`;
- `Description` optional;
- `LifecycleStatus`: Active, Paused, Archived;
- `ActiveRevisionId`;
- `ScheduleGroupId` optional;
- audit timestamps/actors;
- concurrency token.

### SearchRevision

- `Id` UUIDv7;
- `SearchDefinitionId`;
- `RevisionNumber` monotonic per search;
- `OriginalUrl`;
- `NormalizedUrl`;
- `TimeZoneId`;
- `Priority`;
- `MaxPages`;
- `MaxDuration`;
- `RetryPolicyCode`;
- `RequiredAgentCapabilities`;
- `CreatedAt`, `CreatedBy`;
- `ChangeReason`.

Revision не обновляется после создания.

### ScheduleGroup

- `Id`, `OrganizationId`, `Name`;
- `ScheduleExpression` в выбранном формате;
- `TimeZoneId`;
- `Enabled`;
- `ValidFrom/ValidTo` optional;
- ограничения одновременных запусков;
- audit/concurrency.

## 8. Ограничения целостности

- RevisionNumber уникален внутри SearchDefinition.
- ActiveRevision принадлежит тому же SearchDefinition.
- URL допускает только `https` и разрешённый host источника.
- URL не содержит credential, fragment и запрещённые параметры.
- `MaxPages`, длительность и повторы имеют серверные минимумы/максимумы.
- Archived search нельзя запустить.
- Paused search нельзя запустить расписанием; ручной запуск требует явного resume
  либо отдельного привилегированного override, если он будет нужен.
- Одновременное изменение защищено concurrency token.
- Физическое удаление ревизии запрещено при наличии запусков.

## 9. URL и приватность

- Хранить исходный URL для воспроизводимости и нормализованный для сравнения.
- Не удалять неизвестные query-параметры без доказательства их незначимости.
- Секретные параметры запрещены и маскируются до логирования.
- Контекстные параметры площадки могут быть значимыми; нормализация версионируется.
- UI показывает домен, название и сокращённый URL, полный — только по праву.

## 10. Расписание

- Формат расписания выбирается отдельно и не выставляется пользователю как сырой
  cron без необходимости.
- UI предлагает понятные режимы: вручную, ежедневно, дни недели, несколько окон.
- В БД хранится нормализованное правило и временная зона.
- Переходы летнего времени обрабатываются детерминированно, хотя бизнес-таймзона
  для Московской области обычно стабильна.
- Пропущенный запуск не догоняется бесконечно; используется политика misfire.
- Одно расписание не создаёт второй активный SearchRun той же ревизии.

## 11. API

| Use Case | Метод/маршрут | Идемпотентность |
|---|---|---|
| ListSearchDefinitions | GET collection | Не требуется |
| GetSearchDefinition | GET item | Не требуется |
| CreateSearchDefinition | POST | Idempotency-Key рекомендуется |
| UpdateSearchDefinition | PUT/PATCH + version | Concurrency token |
| PauseSearchDefinition | POST action | Повтор безопасен |
| ResumeSearchDefinition | POST action | Повтор безопасен |
| ArchiveSearchDefinition | POST action | Повтор безопасен |
| RunSearchNow | POST action | Idempotency-Key обязателен для клиента |
| ListSearchRevisions | GET subresource | Не требуется |
| ValidateSearchUrl | POST validation | Без сохранения |

Точные URL закрепляются при реализации, но действия не маскируются универсальным
endpoint «change status».

## 12. Межмодульный контракт

Administration публикует запрос на создание запуска с:

- SearchDefinitionId;
- SearchRevisionId;
- TriggerType;
- RequestedBy;
- RequestedAt;
- IdempotencyKey;
- Priority.

Collection возвращает идентификатор SearchRun или существующий результат той же
идемпотентной команды. Administration не создаёт CollectionTask напрямую.

## 13. UI

### Список

Колонки:

- название;
- источник;
- территория;
- состояние;
- расписание;
- последняя успешная попытка;
- последняя ошибка;
- следующая плановая попытка;
- активная ревизия;
- действия.

Фильтры: состояние, источник, группа расписания, ошибка, текст.

### Карточка/редактор

- основная информация;
- URL с проверкой;
- расписание;
- лимиты;
- совместимые агенты/capabilities;
- история ревизий;
- последние запуски;
- аудит.

### Состояния

- нет поисков — объяснение и кнопка создания;
- URL не разрешён;
- конфликт редактирования;
- поиск paused/archived;
- ручной запуск уже существует;
- нет совместимого Agent;
- сервер принял запуск;
- частичная недоступность истории запусков не должна блокировать редактирование.

## 15. Ошибки и конкурентность

| Ситуация | Поведение |
|---|---|
| Два администратора меняют поиск | Второй получает conflict и актуальную версию |
| Повтор Create с тем же idempotency key | Возвращается прежний результат |
| Ручной запуск уже активен | Возвращается существующий SearchRun либо понятный conflict |
| Расписание сработало во время pause | Новый запуск не создаётся, фиксируется skip reason |
| URL содержит другой домен | Validation error до сохранения |
| ScheduleGroup выключена | Поиск остаётся активным, но следующий запуск отсутствует |
| Collection временно недоступен | Команда запуска сохраняется через утверждённый надёжный механизм или возвращает контролируемую ошибку без ложного успеха |

## 16. Аудит и наблюдаемость

Аудит:

- создание;
- новая ревизия с причиной;
- pause/resume/archive;
- изменение группы расписания;
- ручной запуск;
- изменение лимитов и capabilities.

Метрики:

- активные/paused/archived поиски;
- ручные и плановые запросы запуска;
- skipped по причине активного запуска/pause/лимита;
- ошибки валидации URL;
- searches без успешного запуска дольше порога.

## 17. Тестирование

| Уровень | Случаи |
|---|---|
| Unit | URL policy, границы лимитов, revision decision, pause/archive, schedule calculation |
| Integration | уникальность ревизии, optimistic concurrency, immutable revision, транзакция active revision |
| API | permissions, validation, idempotency ручного запуска, Problem Details |
| Security | чужая OrganizationId, Manager без manage, маскирование URL |
| Architecture | Administration не создаёт CollectionTask напрямую |
| E2E | создать → проверить → запустить → изменить → увидеть две ревизии → pause |

## 18. Вертикальные этапы

1. Создать и просмотреть один поиск без расписания.
2. Изменить URL и увидеть две ревизии.
3. Выполнить ручной запуск через контракт Collection-заглушки.
4. Добавить ScheduleGroup и расчёт следующего запуска.
5. Добавить pause/resume/archive, аудит и административную историю.

Каждый этап включает UI, API, данные, права и тесты своего сценария.

## 19. Definition of Ready

- утверждены права FP-002;
- определён первый разрешённый host Авито;
- выбрана бизнес-таймзона;
- согласованы безопасные начальные MaxPages/MaxDuration;
- выбран формат расписания и misfire policy;
- определено, какие query-параметры URL считаются секретными/запрещёнными;
- согласован межмодульный контракт создания SearchRun.

## 20. Definition of Done

- администратор управляет поиском только через ERP;
- значимое изменение создаёт revision;
- старый SearchRun сохраняет ссылку на старую revision;
- ручной и плановый запуск не создают неконтролируемые дубли;
- pause и archive имеют разный смысл;
- URL проверяется и не раскрывается в логах;
- права и IDOR покрыты тестами;
- audit и метрики доступны;
- E2E-сценарий зелёный.
