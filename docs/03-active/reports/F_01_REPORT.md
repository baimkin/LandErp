# F-01 — группы поиска и сохранённые фильтры

Дата: 2026-09-26. Ветка: `codex/f-01-search-groups-filters`.
База: `243a61f8b73fb4e1c89262cac6b825df6c3ae407`.

## Выполнено

- На /incoming «Сохранённые фильтры» остаются общими для организации.
- «Все группы» и группы без вложенных поисковых ссылок используют существующий
  серверный отбор через наблюдения → задания → поиски группы. Список поисков
  не копируется в сохранённый фильтр, поэтому новые поиски охватываются автоматически.
- Изменение условий сохраняет выбранный ID. Обычное применение не вызывает запись.
  Кнопка редактирования открывает существующие поля условий. Через «Сохранить фильтр»
  доступны название, группа, «Сохранить изменения» и «Сохранить как новый».
- Update сохраняет ID и sort_order, обновляет имя/группу/условия одной SQL-командой
  с organization_id, active и expected version. При конфликте черновик остаётся;
  доступна явная загрузка актуальных сохранённых условий.
- Сервер проверяет права Incoming.Read/Process и доступность группы организации.
  Сохранение держит группу под FOR SHARE до завершения транзакции.

## Совместимость и решения

Новой migration нет. JSON schemaVersion=2 использует SearchGroupId;
SearchConfigurationId оставлен в контракте для чтения старого JSON и равен null
при новых записях. Колонка search_group_id синхронизируется с новым условием
и по-прежнему используется для сортировки/уникальности названия.

V1 разрешается при чтении без записи в БД. Если поиск существует в организации,
его группа активна и не противоречит старым метаданным, возвращается групповое
условие. Имя, ID, версия и остальные условия сохраняются. V2 записывается только
по явному сохранению. У V1 без конкретного поиска метаданные не превращаются
в новое ограничение: фильтр остаётся без группы, сохраняя прежнюю семантику.

Удалённый поиск, отсутствие/недоступность группы или противоречие метаданных
оставляют исходный фильтр без преобразования. Он остаётся в списке с сообщением,
применение и update блокируются. Сообщение содержит имя/ID фильтра, поиска и
групп и варианты для владельца: восстановить связь, подтвердить конкретную
группу либо явно снять ограничение. Автоматического решения этих случаев нет.
В интерфейсе явно указано, что при таком выборе выдача осталась от предыдущих условий.

Рабочие данные не читались: наличие таких случаев в существующей БД не установлено.
Если они обнаружатся при ручной приёмке, требуется отдельное решение владельца
до зависимого изменения данных. Этот Gate не содержит массового преобразования.

## Ограничения и ручная приёмка

Браузер, Server, общий foundation-скрипт и полный suite не запускались.
Commit/push/merge/rebase не выполнялись; main не изменён. Визуальная приёмка не пройдена.
Ни одна следующая F/M/C/T/U/K задача не начиналась.

Владельцу на /incoming проверить:

1. Селектор групп без отдельных ссылок, выбор группы с несколькими поисками.
2. Выбор фильтра → редактирование условий → разовое применение: выбранный фильтр
   остаётся, его сохранённые условия не изменяются до явной записи.
3. Изменение названия/группы/условий и сохранение того же фильтра; копия с другим именем.
4. Две вкладки: сохранение из второй со старой версией даёт конфликт; загрузка
   сохранённых условий заново позволяет проверить актуальное состояние.
5. Старые фильтры и возможные сообщения о неоднозначной привязке; такие записи
   не исправлять массово без решения владельца.
