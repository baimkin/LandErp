# FP-063 — Второй источник объявлений

**Версия:** 0.1  
**Статус:** Черновик  
**Плановая реализация:** после стабилизации и измерения адаптера Авито  
**Модули:** Collection, PropertyCatalog  
**Зависимости:** FP-010–FP-015, FP-024

## 1. Результат

Подключён второй источник (кандидат — ЦИАН) через тот же управляемый поток:
ручные поисковые URL, выдача/карточка, качество, очередь и история. Источник не
ломает Avito adapter и помогает находить дубли реальных объектов.

## 2. Принцип адаптера

Каждый источник реализует версионируемые capabilities: validate search URL,
collect list, collect details, classify page и normalize source-specific fields.
Каноническая модель не теряет исходное значение и не требует от всех источников
одинакового набора полей.

## 3. Поток внедрения

1. Проверить допустимый способ доступа и условия площадки.
2. Собрать реальные fixtures выдачи/карточки/ошибок.
3. Добавить SourceCode и capabilities без `if source` по общей системе.
4. Запустить одну ссылку/один Agent в canary.
5. Измерить полноту, блокировки и дубли.
6. Включать остальные ссылки постепенно.

## 4. Дедупликация

Уникальность Listing остаётся `(SourceCode, ExternalId)`. Межисточниковое
совпадение создаёт `PossibleMatch` FP-024, а не один Listing. Цена и описание
каждого источника сохраняются независимо.

## 5. Операционные ограничения

Отдельные rate limits, browser profile, pause/kill switch, adapter release и
quality thresholds. Проблема второго источника не останавливает первый.

## 6. Тесты и DoD

- общий pipeline без копирования доменной логики;
- fixture coverage page kinds;
- source IDs не сталкиваются;
- сбой/пауза изолированы;
- межисточниковая подсказка объяснима;
- настройки/права/мониторинг работают;
- нет обхода CAPTCHA или запрещённого канала.

## 7. Открытые вопросы

- какой источник второй;
- допустимый способ авторизации/сбора;
- поля и особенности выдачи;
- приоритет и число поисковых ссылок.
