## Результат

- Одна форма `CaseCommunication` в полной карточке и боковом просмотре очереди.
  Действия и заголовок — «Записать общение»; «Сохранить» и «Отмена».
- Видимые кнопки: Звонок / Переписка / Встреча, сохранены Эл. почта / Другое.
  Новая «Переписка» хранится прежним значением «Мессенджер»; старые «Телефон»,
  «Сообщение» и остальные сохранённые значения не преобразуются.
- Когда: дата и текстовое HH:mm, по умолчанию один текущий момент по МСК.
  «С кем» по умолчанию Продавец. Дата/время и суммы проверяются у полей.
- Один основной текст «Что обсудили»: первоначально три строки, CSS field-sizing
  увеличивает поле по содержимому, ручное увеличение остаётся. Используется Outcome
  с прежним пределом 1000 символов, содержательный текст от 3 символов обязателен.
- Три видимые необязательные цены: продавец / наше предложение / согласовали.
  Текстовые поля без spinner, пробелы разрядов и десятичная запятая; серверное
  округление RUB прежнее. Согласованная цена берётся только из своего поля.
- Следующая задача всегда видна: название, дата, необязательное HH:mm,
  ответственный, Сегодня/Завтра/Без срока. Пустое название не создаёт задачу;
  заполненное создаёт независимую WorkTask, в том числе без срока.
  Исполнитель по умолчанию — Assignment объекта, допустимые назначения из T-01.
- Поля цен и задачи не скрыты в details. На узких экранах строки переносятся.
- В боковом просмотре сохранён выбор материалов; загрузка через существующий
  AddAttachmentAsync после подтверждённого общения. Ошибка отдельного материала
  сообщает, что общение уже сохранено, и не оставляет его доступным для новой отправки.
  В полной карточке материалы по-прежнему добавляются штатным блоком документов.
- Блок задач после сохранения общения обновляется вместе с версией карточки.

## Атомарность, права и совместимость

Новый `RecordCaseCommunication` оборачивает прежние поля `AddNegotiation` и
необязательную `CommunicationTask`. Обе команды используют общий
AddNegotiationCoreAsync; нового сервиса и новой сущности нет.

Одна PostgreSQL-транзакция сохраняет CaseNegotiation, WorkTask, увеличение версии
case, timeline и audit receipt. Общие с T-01 ApplyTaskDetailsAsync проверяют
название, тип, срок и допустимого исполнителя. Ошибка не оставляет только общение.
WorkTaskId объекта не заменяется, существующие задачи не изменяются.

Сохранены организация/видимость через ProcurementWorkContext и VisibleCases;
внутри транзакции добавлена проверка действующего сотрудника и блокировка организации.
Проверяется ExpectedCaseVersion. Выявленное отсутствие этой проверки в прежнем
AddNegotiation исправлено на общей границе. Запрещены rejected/monitor до штатного
возобновления, acquired запрещён явно (ранее запрет был на кнопке UI).
Назначение задачи не расширяет права на объект.

Replay через существующий ProcurementCommandReplay. Новый action
`CaseCommunicationRecorded` хранит ID общения, текст, цены и snapshot созданной задачи;
клиент повторяет неизвестный результат с исходным payload и тем же CommandId.
Повтор проверяет текущие права, возвращает исходный ID до проверки устаревшей версии
и не меняет уже независимо выполненную задачу. У старого AddNegotiation сохранены
тип payload, имя action и audit shape: прежние receipt не ломаются добавлением полей.

Редактирования сохранённых переговоров в текущем API/UI нет. Оно не добавлялось;
задача создаётся только при первом сохранении, дальнейшие изменения — через T-01.
Связь для истории записана в существующем audit, двусторонней синхронизации нет.
Текст новых записей хранится только в Outcome. Старые Conditions/Comment/NextStep
сохранены и доступны через существующее чтение/историю. Пустые цены новой записи
остаются null и не очищают предыдущие ненулевые значения. Рабочая цена объекта
не меняется по новому правилу; используется прежнее чтение переговорных цен.

Черновик остаётся при ошибках; при конфликте можно обновить версию без потери полей.
После неизвестного результата форма заморожена до повтора исходной команды.
После подтверждённой записи повтор не используется для исправления ошибки вложения.
