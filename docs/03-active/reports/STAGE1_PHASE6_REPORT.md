## Результат

Phase 6 `Organization administration` реализована как единая страница
`Организация` с вкладками `Структура / Сотрудники / Должности`. Визуальная и
сценарная основа взята из утверждённого владельцем
`landerp_organization_v1_3.html`; в репозитории сохранена полная версия этого
reference prototype без демонстрационных данных в production UI.

Данные страницы читаются из PostgreSQL в границах текущей организации и scope.
Структура показывает дерево `Отдел → Команда → Сотрудники`, руководителей,
должности, состояния и счётчики. Работают поиск, фильтры, раскрытие дерева и
показ архивных элементов. Отдельный прежний экран сотрудников объединён с этой
страницей; старый URL `/employees` открывает вкладку сотрудников.

Поддержаны создание и редактирование отделов, команд и должностей, а также их
архивирование и восстановление без физического удаления и скрытых каскадов.
Архивирование блокируется при активных назначениях/зависимостях. Сохраняются
описания, руководители, состояние и optimistic concurrency.

Администратор может создать сотрудника напрямую по логину, назначить отдел,
команду, должность, руководителя, роль и одну из пяти областей доступа. Сервер
генерирует временный пароль, хранит только verifier и показывает открытый пароль
один раз. Первый вход может быть ограничен обязательной сменой пароля. Реализованы
сброс временного пароля, отключение и восстановление сотрудника, немедленный отзыв
сессий и запрет отключения собственной записи/последнего активного Owner.
Приглашения сохранены как дополнительный существующий сценарий.

Должность и доступ остаются независимыми: изменение должности не меняет роль или
scope. Все изменения структуры, назначений, учётных данных и состояния сотрудника
пишутся в append-only audit без паролей и одноразовых кодов. Изменения Identity,
Employee и audit для credential/state операций объединены транзакцией.
