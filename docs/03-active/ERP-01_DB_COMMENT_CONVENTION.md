# ERP-01 — комментарии объектов PostgreSQL

**Статус:** обязательная convention ERP-01  
**Применяется:** ко всем production migrations LandErp, начиная с первой схемы.

## Правило

Технические имена schema/table/column/index/constraint остаются на английском языке и следуют принятому naming convention.

В самой PostgreSQL должны храниться русские комментарии, доступные из DBeaver, pgAdmin, DataGrip и других клиентов БД:

- каждая бизнес-таблица получает осмысленный русский комментарий;
- каждый неочевидный бизнес-столбец получает русский комментарий;
- важные технические таблицы и столбцы получают комментарий, если без него назначение или жизненный цикл можно понять неверно;
- очевидные технические поля (`id`, однозначный `created_at` и подобные) могут оставаться без комментария, если семантика действительно однозначна.

Комментарий объясняет бизнес-смысл, источник или важное ограничение поля, а не просто переводит английское имя.

Пример желаемого результата:

```sql
COMMENT ON TABLE investment_projects
IS 'Инвестиционные проекты по приобретённым земельным объектам';

COMMENT ON COLUMN investment_projects.acquired_at
IS 'Дата фактического приобретения объекта. Не является датой создания записи в LandErp.';
```

## Реализация

Комментарии являются частью схемы БД и должны создаваться и изменяться управляемыми EF Core migrations через `HasComment`, provider metadata или эквивалентный поддерживаемый механизм.

Недостаточно хранить описание только в C# XML comments, Markdown-документации или UI.

При review migration необходимо проверить сгенерированный SQL и после apply убедиться через PostgreSQL metadata, что обязательные `COMMENT ON TABLE` / `COMMENT ON COLUMN` реально присутствуют и видны клиентам БД.

Если новая migration создаёт бизнес-таблицу или неочевидное бизнес-поле без требуемого русского комментария, migration считается неготовой к приёмке.
