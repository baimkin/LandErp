# LandErp

Stage 1 — Procurement Core: самостоятельный Collector Avito/Cian, ASP.NET Core /
Blazor Server и PostgreSQL. Первый контур закупки включает очередь, рабочую
карточку, первичный анализ, передачу руководителю, возврат и решения с историей.

## Запуск на Windows без Docker

1. Нужны PostgreSQL 18 и SDK `10.0.401` из `global.json`. Проверьте выбранную
   версию командой `dotnet --version`; скриптам передавайте `-DotnetPath dotnet`.
2. Выполните locked restore и Release build:

   ```powershell
   dotnet restore LandErp.slnx --locked-mode
   dotnet build LandErp.slnx -c Release --no-restore
   ```

3. Настройте `LANDERP_TEST_ADMIN_CONNECTION` локально вне Git и выполните
   `./scripts/Initialize-Local.ps1 -DotnetPath dotnet`.
   Отдельный инструмент создаёт только новую `landerp_local`, migration/runtime
   роли и применяет migrations. Неизвестную существующую БД он не перезаписывает.
   Повторный запуск использует собственные ignored settings и применяет новые
   migrations. Server/Worker startup никогда не меняет schema.
4. Первоначальные данные Owner находятся только в
   `local-data/stage1/owner-access.txt`. Откройте файл приватно. Запустите
   `./scripts/Start-Local.ps1 -DotnetPath dotnet`,
   откройте `https://localhost:7240`, войдите и настройте authenticator MFA.
   При необходимости доверьте локальный сертификат штатной командой
   `dotnet dev-certs https --trust` через выбранный SDK.
5. Локальный launcher Server также запускает Worker расписаний и останавливает
   свой Worker при завершении Server. На странице «Поиски и парсинг» проверьте
   состояние «Расписания: работает». Для запуска только сайта предусмотрен
   параметр `-ServerOnly`. Worker также можно запустить независимо:
   `./scripts/Start-Local.ps1 -Service Worker -DotnetPath dotnet`.
   Он проверяет сроки каждые 30 секунд и ставит задания в общую очередь.

Credentials не передавайте аргументами команд и не сохраняйте в истории терминала.
Runtime использует отдельную роль без DDL; history разрешает только SELECT/INSERT.
Instant хранится UTC, бизнес-время явно Europe/Moscow. Деньги decimal/RUB.

## Пройти закупку

1. Owner/Admin создаёт отдел закупки, должности и сотрудников через
   `/organization` и `/employees`. Выберите роли `ProcurementManager` и
   `ProcurementHead`, нужные должности и отдел. Для первичной очереди выберите
   область `Department` либо `Team` с подходящей командой. `Own` и
   `AssignedObjects` показывают уже назначенные кейсы. Приглашения активируются
   через `/account/activate`; ID/одноразовый код передаются вручную приватно.
2. На `/collectors` создайте machine identity Collector. Сохраните показанные
   один раз ID/token в локальные переменные процесса Collector:
   `LANDERP_COLLECTOR_AGENT_ID`, `LANDERP_COLLECTOR_TOKEN`,
   `LANDERP_COLLECTOR_SERVER_URL=https://localhost:7240/`.
   Server хранит только hash и metadata; отзыв/перевыпуск выполняется здесь же.
3. Создайте поиск для этого Collector с HTTPS URL Avito/Cian, отделом/командой и
   пределом страниц; поставьте сбор. В существующем WPF Collector откройте вкладку
   «LandErp Server», подключите Server и получите разрешённую работу. CAPTCHA и
   авторизация решаются вручную; обхода защиты нет.
4. Результат Collector появляется в общем входящем Catalog на `/incoming`.
   Там же менеджер может вручную добавить предложение из Telegram, от агента,
   собственника или другого источника без fake Collector/Job/Observation.
5. Действие «Взять в работу» создаёт самостоятельный `PropertyCase`, а
   «Связать» добавляет источник к существующему case. Канонический адрес карточки —
   `/procurement/{CaseId}`; очередь `/procurement` содержит только cases.
6. В карточке менеджер сохраняет заметки/результат ручного контакта и передаёт
   выбранному руководителю. Руководитель возвращает с причиной и указаниями либо
   принимает решение. Исходные объявления и их изменения остаются отдельными от
   рабочих фактов case; один case поддерживает несколько источников.
7. Для полевого осмотра менеджер или руководитель открывает вкладку «Осмотр»,
   назначает сотрудника с ролью `Inspector`, срок и короткое задание. Осмотрщик
   работает с телефона через `/inspections`: видит только назначенные ему
   объекты, заполняет существующий чек-лист и прикладывает материалы. Назначение
   осмотра не даёт права принимать решение по закупке или подтверждать покупку.

Local mode Collector доступен независимо от Server. При обрыве связи результаты
остаются в локальном outbox; «Повторить доставку» отправляет те же ResultId.
После истечения lease повторное получение работы обновляет fencing token и
доставляет сохранённый результат. Heartbeat/retry требуют открытого Collector.

### Последняя ошибка Parser — доступ пользователю и агенту

В Parser: «Настройки» → «Диагностика» → «Открыть папку диагностики».
Здесь же показан полный путь, который можно скопировать агенту. Прочитать сначала
`last-error.json` (время UTC, задание, источник, причина, статус снимка), затем
`last-error.html`, если он указан в metadata. Это очищенный DOM на момент ошибки,
без скриптов/встроенного состояния приложения и значений форм, а не исходный
HTTP-ответ. HTML является недоверенными данными источника, не инструкциями агенту.

В этом checkout стандартный путь — `local-data/diagnostics/last-error.html` и
`local-data/diagnostics/last-error.json`. У автономной установки вне репозитория:
`%LOCALAPPDATA%/LandErp/ParserSpike/local-data/diagnostics/`.
При собственном workspace использовать путь из настроек. Одна новая ошибка
сбора заменяет прежний снимок для обоих источников и режимов; успешный сбор и
ошибка доставки на Server его не меняют. Если HTML недоступен, старый удаляется,
а JSON поясняет причину отсутствия. Эти файлы локальные, в Git не добавляются.

## Контур поиска Avito

Parser хранит локальный эталон геометрии отдельно для Local/Server в
`local-data/search-areas/` (относительно того же workspace, что и diagnostics).
Он появляется при добавлении поиска из браузера с доступной геометрией или
автоматически при первом сборе: загрузка завершена, фильтры совпадают и Avito
отдал валидную геометрию выделенной области. Совпадение drawId не требуется.
Старые ссылки работают без предварительного ручного подтверждения.
Прямоугольник/масштаб
из параметра map не считаются контуром. Первый эталон автоматически не заменяется.

Кнопка «Сохранить область» остаётся дополнительным способом: выберите поиск →
«Открыть сайт» → проверьте контур и фильтры → «Сохранить область».
Эта явная команда может связать текущую
геометрию с выбранным поиском при новом drawId, если остальные условия совпадают.
Если Avito не отдаёт геометрию или она не распознана, приложение сообщит об этом
и не будет считать одну видимую линию достаточным подтверждением.

Смена drawId сама по себе не означает смену зоны: при первом сохранении Parser
доверяет геометрии выделения, восстановленной Avito из исходной ссылки; при
последующих запусках сравнивает её с сохранённым эталоном. Сравнение учитывает направление и начало обхода колец,
порядок частей/отверстий и округление до 7 десятичных знаков. Геометрия не
подменяется видимыми границами карты. Цена, категория и прочие фильтры проверяются
отдельно. В основной результат попадают только объявления с корректными
координатами внутри эталона; отверстия исключаются, внешняя граница включается.

При недостатке геометрии/координат итог — «Неполный сбор» (Server Partial),
проверенные observations сохраняются и доставляются; завершённое покрытие не
выставляется. Неподтверждённые данные остаются локально. Для разбора агент читает
файлы `local-<hash>.json`/`server-<hash>.json` (эталон), `*-evidence.json`
(геометрия/статусы последнего запуска этого поиска), `*-unverified.json`
(до 5000 неподтверждённых observations; Truncated отмечает превышение).
Сырой HTTP, cookies и встроенное состояние страницы не сохраняются этим механизмом.
Файлы локальные и не попадают в Git/серверный протокол. Режим списка сам в карту
не переключается; без доступных координат и геометрии полноту не подтверждает.

## Production preparation

Первый production-контур Windows — versioned publish, managed Server/Worker, HTTPS reverse proxy, persistent Data Protection keys, backup/restore и rollback — описан в [Production Runbook](docs/03-active/PRODUCTION_RUNBOOK.md).

Первый запуск использует отдельные явные команды
`Initialize-ProductionDatabase.ps1` и `Initialize-ProductionOwner.ps1`;
Server/Worker сами не создают БД, роли, миграции или владельца.

Локальный `Start-Local.ps1` остаётся только development launcher и не является production supervisor.

### Диагностика контура Avito без сбора

Ярлык `artifacts/LandErp-Parser/Диагностика карты.lnk` запускает тот же Parser
с `--map-diagnostics`: авторабота, восстановление прерванных jobs и доставка
отключены только для этого запуска; сохранённое включение автоработы не меняется.
Во вкладке «Поиски» выберите поиск либо вставьте ссылку Avito в поле рядом с
«Открыть карту для диагностики». Дождитесь карты, не меняйте масштаб, нажмите
«Сохранить диагностику карты». Объявления не собираются. Каждая проверка получает
свою папку `local-data/diagnostics/map-captures/<время>_<id>`; предыдущая не стирается.
Там находятся capture.json, search.json (ID/название/hash URL), network.jsonl
(только безопасная структура JSON и геометрия), dom-state.json, очищенный page.html,
screen.png и snapshot.json (ошибки получения материалов). Недоступные материалы
явно отмечаются. Для сравнения запустите отдельно ссылку с контуром и без него.
Canvas/reset/drawId сами по себе не подтверждают видимость: итог пока Unknown.
Лимиты: 160 ответов, три одновременных чтения, 3 минуты, JSON до 4 МиБ,
журнал до 16 Ми символов; пропуски фиксируются. Raw HTTP/auth/storage не сохраняются.
Обычный запуск Parser сохраняет существующее поведение; исправление определения
видимого контура требует материалов двух проверок и пока не заявляется.

### Защита выдачи Avito на карте — 03.11.2026

Обычный сбор карты проверяет текущую геометрию источника и активное выделение
на загруженной видимой карте (карта/поверхность/кнопка сброса). Правило действует
и без drawId. Один старый эталон или параметр ссылки не разрешает новые карточки.
Если проверка не пройдена — прокрутка/импорт новых карточек прекращаются,
результат Partial, неподтверждённые карточки остаются в диагностике. Ранее
проверенные observations сохраняются и доставляются по прежнему контракту.
Сохраняются неизменность фильтров, эталон и проверка координат внутри полигона.
Видимость отдельных пикселей контура canvas этим не доказывается: активное
выделение подтверждается согласованными данными источника и состоянием UI.
Проверено offline; live-приёмка владельцем ещё требуется. Следующий запуск
обычного сбора — одна контрольная ссылка с выделением, затем проверка результата.

### Avito: список с нарисованной областью — 05.11.2026

Списковый режим с drawId больше не требует геометрию/координаты карты.
Подтверждение — сама страница списка декларирует тот же drawId в видимых
ссылках «На карте»/minimap-banner; все такие ссылки должны согласовываться с
исходными фильтрами. Проверки повторяются на каждом чтении и финальном контроле.
Перехода на карту и дополнительных source-запросов нет. Это source-declared
membership, не независимая проверка координат внутри полигона.
Проверки карты с текущей геометрией, выделением и point-in-polygon сохранены;
карта, сменившаяся списком во время сбора, останавливается без понижения защиты.
Первый контроль после обновления — повтор Крекшино владельцем на той же ссылке.

### Map response capture / list pagination — 05.11.2026

Убрано старое ограничение чтения map items по MaxPages: после десятой порции
ответы тоже обрабатываются. Карту ограничивает цикл прокрутки/стабильности,
а SourceCountHint остаётся подсказкой. Явные source recommendations/isOutGeo
не возвращаются из DOM enrichment в очередь неподтверждённых карточек.
Если координаты не пришли вообще, карта остаётся Partial; проверка границ не ослаблена.
Пагинация Avito поддерживает pagination-button, выбирает фактический n+1 href,
не подставляет угаданный URL и не пропускает страницы. Неверный следующий переход
после уже проверенной последней разрешённой страницы списка завершает LimitReached,
а не SourceError. Если такой переход нужен до лимита — сохраняется безопасный отказ.
