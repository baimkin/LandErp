# TP-LOCAL-001 — диагностика JSON браузера

Дата: 2026-09-14. Ветка: spike/001-avito-viability.
Разрешение: прямой запрос владельца добавить диагностику для ручной проверки
карты. Это расширение диагностики TP-LOCAL-001, не реализация парсера карты.
Владелец отдельно попросил не повторять проверки неизменившегося проекта.

## Scope и решения

- Кнопки во вкладке «Диагностика»: начать запись JSON, остановить, показать.
- По умолчанию запись выключена, каждый старт создаёт отдельный JSONL-файл.
- Playwright наблюдает ответы всего контекста Avito/Cian, включая вручную
  открытые вкладки. Новых запросов, route-подмены, replay или внешнего
  перехвата трафика нет. Ручное открытие поиска не запускает сбор объявлений.
- Принимаются JSON MIME-ответы публичных доменов соответствующего источника.
  Личные/auth/contact/messenger/account/платёжные и аналитические endpoints
  исключены. Cookies, заголовки, тела запросов и HTML не сохраняются.
- Файл содержит UTC, источник, HTTP-статус, размер, исход обработки и безопасный
  endpoint без query; длинные/непрозрачные ID пути маскируются.
- Тело преобразуется в схему: имена полей, типы, размеры массивов, образцы.
  Неизвестные строковые и числовые значения не экспортируются. Личные ветви
  исключены, динамические имена ключей маскируются. Вложенный owner/seller
  не получает автоматически право экспортировать ID родительского объявления.
- Допускаются отдельные публичные значения: drawId, счётчик/страница/масштаб,
  явные числовые координаты в диапазоне, известные коды ошибок; ID — только
  у объекта с признаком объявления. Текст описаний, имена, телефоны не пишутся.
- Координаты в схеме ещё не означают подтверждённую точность или связь с
  объявлением. Обработка зоны/меток и запись объявлений из JSON не реализованы.
- Ограничения: 4 одновременных чтения, 500 записей за сеанс, тело до 4 MiB,
  таймаут чтения 5 с, глубина схемы 12, 2000 узлов, до 64 свойств объекта,
  до 3 образцов каждого массива. Просмотр последних 100 записей.
  Пропуски видны в статусе. Ответ без Content-Length может быть получен в
  память целиком до проверки размера; это не механизм потокового дампа.
- Ошибка записи выключает диагностику и увеличивает число пропусков;
  браузерный сбор не должен падать из-за отдельного диагностического файла.
- Ссылки карты по-прежнему сохраняются с map/drawId/фильтрами. Сохранение
  не гарантирует последующее восстановление выделенной области самим Avito.

## Сборка и проверки

Изолированный вывод artifacts/local-001-json, чтобы не заменять exe владельца.
Фактически выполнено локальное восстановление фиксированных зависимостей:

    dotnet restore src/LandErp.ParserSpike.Desktop/LandErp.ParserSpike.Desktop.csproj --locked-mode --ignore-failed-sources -p:NuGetAudit=false -p:ArtifactsPath=C:/.Projects/LandErp/artifacts/local-001-json
    dotnet build src/LandErp.ParserSpike.Desktop/LandErp.ParserSpike.Desktop.csproj --no-restore -c Release -p:ArtifactsPath=C:/.Projects/LandErp/artifacts/local-001-json

Locked restore успешно. Release build: 0 ошибок / 0 предупреждений.
Набор тестов, format и audit не повторялись по запросу владельца; прежние
67 Passed относятся к предыдущей версии и не доказывают работу нового observer.
Новые live/synthetic JSON-ответы этой доработкой пока не проверены —
NotVerified. Никаких автоматических действий на реальном сайте не запускалось.
При сборке найдено и исправлено обращение к отсутствующему OptionsCompact;
финальная версия использует отдельную компактную сериализацию схемы.

## Проверка владельцем

1. Закрыть прежнюю версию, запустить
   artifacts/local-001-json/bin/LandErp.ParserSpike.Desktop/release/LandErp.ParserSpike.Desktop.exe.
2. «Диагностика» → «Начать запись JSON».
3. «Ссылки и очередь»: сохранить ссылку карты, выбрать её,
   нажать «Открыть поиск вручную».
4. В браузере открыть/выделить область, прокрутить правый список.
   «Обработать отмеченные» для исследования ответов нажимать не требуется.
5. Вернуться в приложение → «Остановить запись JSON», затем «Показать JSON».
   Дождаться окончания чтения уже пришедших ответов и обновить просмотр,
   если последняя запись ещё не появилась.
6. Передать указанный файл из local-data/diagnostics/browser-json/.
   Для сравнения рабочей и сброшенной зоны сделать два отдельных сеанса.
   Зафиксировать, какой файл относится к какой зоне.

Если после открытия нет ответов, повторить загрузку карты при включённой записи.
Если MIME не JSON, payload бинарный/закодированный или данные уже в кеше,
этот этап может не дать нужной структуры; это нужно выяснять по результату.
Дальнейшие решения — после разбора журнала: DOM/JSON парсер карты,
координаты, проверка восстановления контура. Сейчас их реализация не начата.
Commit/push не выполнялись, завершить этот диагностический шаг здесь.
