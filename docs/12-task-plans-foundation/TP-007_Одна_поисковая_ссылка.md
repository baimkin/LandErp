# TP-007 — Одна поисковая ссылка

**Статус:** На согласовании  
**Зависимости:** TP-003, TP-005, TP-006, FP-010  
**Результат:** администратор сохраняет один URL Авито с названием и видит неизменяемую Revision 1.

## Входит

- `SearchDefinition` и `SearchRevision` в модуле-владельце Collection;
- административный UI вызывает публичный use case Collection, не владея таблицами;
- `CreateSearchDefinition` vertical slice;
- allowlist `https` и host Авито;
- исходный и нормализованный URL;
- permissions `searches.read/manage`;
- миграция с ограничениями уникальности;
- страница списка и форма создания;
- аудит создания.

Расписание, редактирование, pause и запуск Agent не входят.

## Эталон команды

```csharp
public sealed record CreateSearchDefinitionCommand(
    string Name,
    string LocationLabel,
    Uri OriginalUrl);

public sealed record CreateSearchDefinitionResult(
    Guid SearchDefinitionId,
    Guid SearchRevisionId,
    int RevisionNumber);
```

Use case проверяет право и URL на сервере, создаёт Definition + Revision в одной
транзакции и возвращает DTO, а не EF entity.

## Данные и ограничения

- UUIDv7 identifiers;
- `RevisionNumber = 1`;
- Revision после commit не изменяется;
- URL не содержит fragment/credential;
- неизвестные query parameters не удаляются без утверждённого normalizer rule;
- название имеет длину и optimistic concurrency для будущего изменения.

## UI-состояния

Loading, empty «Поисков пока нет», validation error, forbidden, conflict и
success с переходом к созданному поиску.

## Проверки

- валидная ссылка создаёт две связанные записи;
- HTTP, неизвестный host, credential и слишком длинный URL отклоняются;
- повтор с Idempotency-Key не создаёт дубль;
- Manager без `searches.manage` получает 403;
- audit не содержит полный URL, если он признан чувствительным;
- миграция проверена на PostgreSQL.

## Definition of Done

Один поиск создаётся и читается через UI/API, данные историчны, права и ошибки
проверены integration/E2E тестами.
