## Фактическая матрица

| Состояние и права | Текст / доступные действия |
|---|---|
| Назначенный менеджер, рабочая стадия | Текущий исполнитель; передать руководителю, уточнить данные, наблюдать, отклонить |
| `pending_head`, назначенный руководитель, не автор анализа | Ожидается решение руководителя; продолжить работу, вернуть менеджеру, наблюдать, отклонить |
| Руководитель, источники изменились после передачи | Продолжить работу выключено; пояснение о повторном анализе и переход к источникам. Возврат остаётся доступен |
| Нет подходящих руководителей / менеджеров | Конкретное пояснение о получателе; соответствующее действие недоступно |
| Руководитель, исходный менеджер больше не допустимый получатель | Продолжение, наблюдение и отказ недоступны; можно вернуть другому допустимому менеджеру |
| Другой исполнитель | Имя текущего исполнителя из разрешённого чтения и требуемая роль; без пустого окна решений |
| Доступ только для чтения | Стадия, исполнитель и явное ограничение просмотра; нет действий решения |
| `returned` / `clarify` | Возвращён менеджеру для доработки / требуется уточнить данные |
| `negotiation` / `approved` | Продолжение работы одобрено; покупка ещё не оформлена. Для legacy `approved` без новых данных решения скрыты согласно существующему command handler |
| `monitor` | Объект на наблюдении; решения назначенного менеджера доступны, покупка недоступна до возобновления |
| `rejected` без новых данных | Объект отклонён; повторный анализ после изменения источников. Нет решений и оформления покупки |
| `rejected` с новыми данными | Повторный анализ доступен назначенному менеджеру |
| `acquired` | Покупка оформлена, закупка завершена; новых решений нет, прежняя коррекция покупки по праву сохранена |
| Имя исполнителя отсутствует в чтении | Исполнитель не указан, требуется проверить назначение; имя не придумывается |

Основание: существующие `ReadCardAsync`, `DecideAsync`, `MarkAcquiredAsync`, `TargetsAsync`. `CanManagerDecide/CanHeadDecide` остаются серверными. Дополнительные UI-ограничения повторяют явные запреты handler, не создают новые полномочия. Проверки с Blocker показываются как вопросы, которые нужно учесть: текущий сервер не запрещает этими флагами все решения, и UI не вводит такой запрет.
