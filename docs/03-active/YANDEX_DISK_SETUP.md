# Подключение Яндекс Диска

## Разработка

OAuth-приложение создаётся для доступа к API; единственный требуемый scope —
`cloud_api:disk.app_folder`. Не требуются доступ ко всему Диску и публичные ссылки.
Токен вводится локально, его нельзя передавать аргументом команды, коммитить,
печатать в логи или присылать в чат. Client ID секретом не является.

1. `scripts/Set-YandexDiskConnection.ps1` запрашивает токен скрыто и сохраняет его
   через Windows DPAPI CurrentUser в ignored `local-data/yandex-disk/token.dpapi`.
   Работать с ним может пользователь Windows, который его сохранил.
2. Выполнить locked restore и Release build выбранным .NET 10 SDK.
3. `scripts/Test-YandexDiskConnection.ps1 -DotnetPath <dotnet.exe>` выполняет
   opt-in проверку: два маленьких синтетических файла, повтор без дубля,
   скачивание и SHA-256. Проверка не удаляет файлы: они остаются в `Checks`.
4. `scripts/Start-Local.ps1 -DotnetPath <dotnet.exe>` автоматически подключает
   сохранённые настройки. Инициализация БД выполняется обычным отдельным процессом;
   подключение хранилища и startup не применяют migrations.

Папка приложения появляется в Диске в разделе приложений. Внутри:

```text
LandErp/development/
  Objects/<organization-id>/<case-id>/
    Photos/
    Documents/
    Audio/
    Video/
  Checks/<check-id>/
```

Папки создаются по мере загрузки. В именах файлов только ID, hash и расширение;
адреса объектов и исходные пользовательские имена в облачные пути не попадают.
Смысловые названия остаются в LandErp. Для Яндекс Диска файлы до 500 МиБ
(524288000 байт) передаются прямо из браузера пользователя: Server получает
временную ссылку своим токеном, браузер отправляет байты, Server проверяет
размер и SHA-256 перед доступностью вложения. OAuth-токен браузеру не передаётся.
На устройстве пользователя файл проверяется порциями по 1 МиБ; загрузка имеет
прогресс и отмену. Повтор использует то же вложение, уже успешные файлы пропускаются.
Браузер на сервере для работы ERP не требуется. Галерея и сжатие не входят в этап.
Локальное файловое хранилище и прежний JSON/byte[] путь ограничены 50 МиБ.

Для запуска из изолированной рабочей копии с существующей локальной БД можно
передать `-SettingsPath` с абсолютным путём к существующему
`local-data/stage1/settings.json` и `-LegacyFilesRoot` с прежней папкой файлов.
Для стандартного запуска из основного checkout прежняя папка —
`src/LandErp.Server/local-data/stage1/files`, если `Storage:Root` не переопределён.
`-ListenUrl https://localhost:7241` позволяет выбрать другой порт. Запуск под тем
же Windows-пользователем необходим для доступа к DPAPI и локальным DB settings.
Это не переносит и не объединяет изменения между рабочими копиями.

## Production заказчика — чистая среда

Создать OAuth-приложение под управлением заказчика, авторизовать его аккаунт.
Через secret store/deployment environment задать:

| Настройка | Значение |
|---|---|
| `Storage__Provider` | `YandexDisk` |
| `Storage__YandexDisk__Token` | секретный OAuth-токен заказчика |
| `Storage__YandexDisk__ConnectionId` | новый GUID без дефисов, уникальный для этого подключения |
| `Storage__YandexDisk__Root` | `app:/LandErp/production` |
| `Storage__YandexDisk__MaxFileBytes` | `524288000` |

Личные тестовые файлы не переносятся. Production без настроенного backend
завершает startup с безопасной ошибкой; локальные production-записи запрещены.
Секреты в appsettings.json и в Git не сохраняются. Ротация токена того же
аккаунта/приложения сохраняет ConnectionId и Root; другой аккаунт или другое
приложение требуют новой чистой среды либо отдельного согласованного переноса.
Папка приложения привязана к OAuth-приложению, поэтому замена Client ID также
не является простым способом получить прежние файлы.

## Отключение тестового Диска

Остановить тестовый Server и отозвать доступ LandErp Development в Яндекс ID.
Чтобы последующий локальный запуск писал новые файлы на локальный диск,
переместить `local-data/yandex-disk/settings.json` за пределы этого точного пути
и очистить переменные `Storage__YandexDisk__Token` / `Storage__Provider` в shell
либо открыть новое окно PowerShell. Зашифрованный token.dpapi можно затем удалить
вручную. Скрипт настройки намеренно не заменяет существующее подключение молча.

Ссылки БД на облачные файлы останутся, но чтение отключённого Диска выдаст явную
ошибку. Старые локальные файлы сохраняют работоспособность по своим ключам.
Личные файлы за пределами app-folder приложение не читает и не изменяет.

## Границы пилота

Backend не является backup. До production необходим отдельный проверенный
процесс резервного копирования БД и файлов. Автоматический export/restore,
retention/сверка, AV/quarantine pipeline и публикация инвесторам не реализованы
этим Gate. Чувствительные документы подчиняются ограничениям ADR-005.
Существующая проверка MIME вложений сохранена; полная signature/антивирусная
проверка содержимого требует отдельного среза перед приёмом недоверенных файлов.
Фотографии источников не скачиваются автоматически: сохраняются только файлы,
которые переданы через существующую операцию загрузки вложения в карточку.

Справка: https://yandex.ru/dev/disk/rest/,
https://yandex.ru/dev/id/doc/ru/register-api,
https://yandex.ru/dev/id/doc/ru/tokens/debug-token.

## Проверка после обновления ERP

В существующем приватном production.json задать Storage.YandexDisk.MaxFileBytes =
524288000; токен, ConnectionId и Root рабочего подключения сохранить.
Изменение примера конфигурации не меняет существующий приватный файл автоматически.
Новых migrations для этого этапа нет. После обновления пользователь открывает
сайт со своего телефона/компьютера, выбирает небольшой файл, затем видео и
проверяет прогресс, доступность и скачивание. Отдельный браузер на сервере не нужен.
Если reverse proxy задаёт Content-Security-Policy, connect-src должен разрешать
HTTPS upload host, выдаваемый Яндексом; worker-src — собственные JS workers.
В самом Server дополнительного CSP с запретом внешней загрузки нет.

До provider-подтверждения состояние остаётся незавершённым. После обрыва связи
использовать «Повторить незагруженные» или «Восстановить загрузку» с исходным файлом.
Сохранённые файлы удаляются мягко с прежней историей/правами. Для записи, которая
ни разу не сохранилась в хранилище, сначала требуется восстановление загрузки:
существующая схема не допускает Deleted без файлового ключа. Физического удаления нет.
## Очередь, скорость и этапы — 03.11.2026

Загрузчик передаёт до пяти файлов одновременно. SHA-256 считается по одному
файлу порциями по 1 МиБ; удачная проверка используется снова при повторе в той
же форме. Ожидание server confirmation уже переданного файла не занимает слот
следующей передачи. Local/старый buffered путь остаётся последовательным.
Скорость отображается только при передаче, усредняется за 3 секунды и является
оценкой browser progress. «Файл передан, ожидаем ответ Яндекса» и «Проверяем
сохранение» — отдельные этапы, без скорости. Время этапов/очереди/всего видно
у каждого файла; EventId 1103 UPLOAD_TIMINGS содержит UploadId и check/prepare/
send/response/confirm milliseconds без имени/URL/hash/секретов. При разборе
медленной загрузки достаточно времени этапов и ID; не отправлять сырые signed URLs.
## Просмотр в галерее

Preview фото/видео идёт через авторизованный /api/procurement/attachments/{id}/media,
без раскрытия provider URL. Server передаёт поток/диапазоны, не буферизуя видео
целиком; исходная загрузка остаётся прямой browser → Диск. Доступ и метаданные
проверяются перед чтением, запрещённые/удалённые записи inline не выдаются.
Фото lazy из оригиналов; видео метаданные/кадр lazy через IntersectionObserver.
Поддержка кодека зависит от браузера, без перекодирования. При ошибке скачать оригинал.
