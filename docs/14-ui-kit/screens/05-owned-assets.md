# 05 — Наши объекты

**Статус:** approved UI reference  
**Экран:** список приобретённых земельных активов (`LandAsset`)  
**UI reference:** `docs/14-ui-kit/prototypes/landerp_owned_assets_v1_2.html`

## Назначение

Экран содержит только уже приобретённые активы. Кандидаты, объявления и объекты до завершения покупки остаются в контуре `PropertyCase` / закупки и сюда не попадают.

Покупка не является отдельным верхнеуровневым экраном: оформление сделки завершается внутри `PropertyCase`. После подтверждённого приобретения создаётся/активируется связанный `LandAsset`, а исходный `PropertyCase` сохраняется как история поиска, проверки, переговоров и покупки.

## Что должно быть видно в списке

Для каждого объекта быстро показываются:

- объект, бизнес-ID и кадастровый номер;
- текущее операционное состояние;
- юридические владельцы и доли;
- цена и дата покупки;
- краткое состояние работ и фактических дополнительных вложений;
- разделение / количество лотов;
- состояние продаж;
- наличие и число экономических участников;
- следующее требуемое действие.

Список предназначен для управления активами, а не для показа всей финансовой аналитики проекта. Детальная экономика открывается в карточке объекта.

## Правая карточка

Клик по строке открывает краткий drawer без ухода со списка. Он показывает:

- фото и основные реквизиты;
- цену и дату покупки;
- юридическое владение;
- краткую сводку: дополнительные вложения, лоты, продажи, инвесторы, полученная выручка;
- текущие работы / разделение / продажи;
- следующее действие;
- быстрые входы в полную карточку `LandAsset`.

Drawer — обзор, а не место для полноценного ведения работ, разделения, инвестиций или продаж.

## Критические бизнес-правила

1. `LandAsset` означает приобретённый/подтверждённый земельный актив и не равен `PropertyCase`.
2. Юридическое владение и экономическое участие инвесторов — разные модели и не должны вычисляться друг из друга.
3. У объекта может быть несколько юридических владельцев с долями.
4. Экономических участников может быть больше, чем юридических владельцев. Например 30% зарегистрированы на компанию, но внутри этой доли экономически участвуют несколько инвесторов и собственный капитал компании.
5. После разделения исходный актив не исчезает из истории происхождения.
6. Зарегистрированные новые участки становятся дочерними `LandAsset`; планируемые части до регистрации остаются `ProjectLot`/планом, а не юридическими участками.
7. Отправка в продажу относится к конкретному продаваемому активу/лоту.

## UX

Таблица должна оставаться спокойной и быстро сканироваться. Не использовать жирный шрифт для каждой первой строки каждой колонки. Акцентировать только название объекта, важные суммы/статусы и следующее действие. Вторичный текст — regular.

Не использовать микротекст ради плотности: служебный текст должен оставаться читаемым на обычном desktop-масштабе. Высота строк должна расти под содержимое; текст не должен накладываться друг на друга.

Новые экраны реализовывать через текущие LandErp tokens/components, без Bootstrap. Reference HTML задаёт композицию и UX, но его demo data/JS не являются backend-моделью.

## Связанные планы

При реализации сверить модель с `FP-041`, `FP-044`, `FP-045`, `FP-046` и инвесторскими планами. Если старые планы подразумевают автоматическое превращение покупки непосредственно в `InvestmentProject`, приоритет у утверждённой продуктовой границы: сначала приобретённый `LandAsset`, затем при необходимости отдельный `InvestmentProject`.
