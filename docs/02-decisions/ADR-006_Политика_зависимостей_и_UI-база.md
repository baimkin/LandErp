# ADR-006 — Политика зависимостей и UI-база

**Статус:** Принято  
**Дата:** 6 сентября 2026 года  
**Владелец решения:** владелец продукта и технический владелец  
**Затрагивает:** все проекты solution, Blazor UI, Agent, тесты и CI

## 1. Решение

LandErp использует минимально достаточный набор внешних зависимостей. Минимализм
не является самоцелью: библиотека добавляется, когда её польза выше стоимости
обновлений, лицензирования, рисков цепочки поставки и поддержки командой.

Для UI принимается локальный Bootstrap CSS, поставляемый стандартным шаблоном
Blazor, как базовый набор reset/grid/utilities/forms. Поверх него создаются
собственные компоненты Blazor и дизайн-токены Land ERP. Готовая сторонняя Blazor
component library в первый контур не добавляется.

## 2. Что означает Bootstrap в Blazor

Bootstrap не является частью runtime Blazor и не даёт серверных или Blazor-
компонентов. Его CSS-файлы обычно включены в создаваемый шаблон проекта как
локальный статический asset. Поэтому их использование не требует отдельного
NuGet-пакета, npm-сборки или внешнего CDN.

Bootstrap JavaScript bundle по умолчанию не подключается. Интерактивное поведение
диалогов, меню и валидации реализуется Blazor и нативным HTML. JS добавляется
только для конкретного сценария, который невозможно качественно закрыть иначе.

## 3. UI-границы первого контура

- локальные Bootstrap CSS assets, без CDN;
- токены Land ERP переопределяют цвет, типографику, размеры, радиусы и focus;
- собственные `Button`, `DataTable`, `Dialog`, `StatusBadge`, формы и состояния;
- системный стек шрифтов, без загрузки web-font;
- без MudBlazor, Radzen, Syncfusion, Telerik и аналогичных UI-наборов;
- без Tailwind, Storybook и отдельного npm-пакета компонентов на старте;
- без Bootstrap JS, пока реальный сценарий не обоснует его подключение.

## 4. Правила добавления зависимости

Перед добавлением NuGet/npm/внешнего бинарного компонента в плане задачи
фиксируются:

1. решаемая задача и почему встроенных средств платформы недостаточно;
2. владелец использования и обновлений;
3. лицензия, зрелость, активность поддержки и известные уязвимости;
4. влияние на размер, запуск, CI, deployment и данные;
5. способ замены или изоляции за локальным интерфейсом;
6. закреплённая версия и набор обязательных тестов.

Транзитивная зависимость оценивается так же, как прямая. Плавающие версии,
неиспользуемые пакеты и CDN-зависимости production запрещены.

## 5. Стартовый допустимый набор

Кроме библиотек платформы ожидаются только зависимости с прямой ролью:

- EF Core и официальный Npgsql provider для PostgreSQL;
- Microsoft.Playwright для Agent и браузерных E2E-тестов;
- Microsoft.Data.Sqlite для локального outbox Agent;
- один согласованный стек unit/integration/architecture тестов.

ASP.NET Core Identity, конфигурация, логирование, HTTP, health checks и базовая
валидация сначала реализуются средствами платформы. Яндекс Диск подключается
официальным REST API через `HttpClient`, без стороннего SDK.

## 6. Не добавлять без измеримой потребности

- MediatR, AutoMapper и универсальные repository/unit-of-work пакеты;
- FluentValidation, если правила сценария ясно выражаются встроенной валидацией;
- RabbitMQ, Kafka, Redis, Elasticsearch и отдельный scheduler;
- PostGIS/NTS до начала утверждённых геосценариев;
- готовые UI-библиотеки, chart/map libraries и web-fonts;
- несколько библиотек, решающих одну и ту же задачу.

Этот перечень не является вечным запретом. Реальная фича может обосновать
добавление в своём FP/TP; системное изменение оформляется новым ADR.

## 7. Контроль

- версии закрепляются централизованно;
- CI проверяет restore/build/test и известные уязвимости;
- неиспользуемые зависимости удаляются отдельным понятным изменением;
- архитектурное ревью проверяет, что пакет не переносит бизнес-логику во внешний
  framework;
- исключение из решения фиксируется в журнале и имеет условие пересмотра.

## 8. Последствия

Плюсы: понятный UI-слой, меньшая поверхность обновлений, отсутствие привязки к
component vendor и возможность использовать удобную CSS-базу без лишней
инфраструктуры. Цена решения — часть сложных ERP-компонентов придётся аккуратно
создать и поддерживать внутри проекта.

## 9. Зафиксированное решение

6 сентября 2026 года владелец продукта подтвердил принцип «только реально нужные
зависимости». Bootstrap оставлен как локальная CSS-основа стандартного шаблона
Blazor; сторонние Blazor component libraries не входят в первый контур.
