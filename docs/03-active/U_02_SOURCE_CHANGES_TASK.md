## Пользовательский сценарий

1. В карточке вместо неконкретного предупреждения и обязательного перехода на «Источники» показать краткое понятное уведомление о доступных изменениях. По возможности обозначить затронутые поля, например «В объявлении изменились цена и фотографии», но только если данные это подтверждают.
2. Вся зона уведомления или явное «Посмотреть изменения» открывает небольшое окно поверх текущей страницы. Основное действие по клику; hover не обязателен и не является единственным способом доступа.
3. В окне указать источник и время наблюдения. Табличное сравнение: поле / было / стало. Показывать только изменённые данные. Денежные значения по общему форматированию без копеек. Для текста — читаемые переносы, для фото — реальные сохранённые изображения и понятные добавления/удаления, если история позволяет это определить.
4. Сразу после успешной загрузки и отображения сравнения показанный набор изменений автоматически считается просмотренным. Отдельной кнопки «Отметить просмотренным» нет. Повторное открытие сравнения доступно через «Источники» и после исчезновения уведомления.
5. Рабочая цена, площадь, описание и подтверждённые факты объекта при просмотре НЕ изменяются. Не добавлять действие «Применить всё» или новый процесс согласования.

## Точность и конкуренция

- Разделить изменения источника между наблюдениями и расхождения источника с рабочими фактами. Это разные вещи. Уведомление показывает изменения источника, окно не должно выдавать рабочую цену за предыдущую цену объявления.
- Если старое значение отсутствует, писать «Предыдущее значение не сохранено», не изобретать сравнение. Отсутствующее поле наблюдения не означает автоматическое удаление прежнего значения.
- Если фото недоступно, показать явное состояние, остальные данные оставить доступными. При полном сбое загрузки сравнения не гасить уведомление.
- Гасится только успешно показанная версия/набор событий. Новое изменение, пришедшее во время просмотра, остаётся непросмотренным; поздний ответ старого окна не должен погасить его. Повторное открытие/запрос отметки безопасны.
- При нескольких источниках явно показывать, к какому относятся изменения. Не смешивать предыдущие значения разных источников; не отмечать просмотренными неоткрытые источники/страницы.
- По согласованию владельца индивидуальный просмотр предпочтителен, если уже поддержан или прост. Если он существенно сложнее, использовать простую общую отметку для команды. Выбранную область явно описать в отчёте; не строить новую систему уведомлений только ради этого.
- Серверные права/организация/доступ к объекту действуют на чтение и отметку просмотра, не только на видимость кнопки. Пользователь, имеющий разрешённый просмотр, должен иметь возможность штатно погасить показанное уведомление в выбранной модели без изменения бизнес-фактов.
