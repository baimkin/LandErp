# Gate PropertyCase V2 — рабочая карточка закупки

## Разрешение и границы

Владелец 2026-09-17 утвердил начало реализации ранее согласованного чек-листа
карточки объекта закупки в отдельной ветке. Визуальный эталон — переданный владельцем
`landerp_property_case_v2_1_purchase.html` (SHA-256
`DE12D6CFF92D9C8B2EC536FB89827BADE1E9BD2A544C1F410508443E1A630AED`).
Макет задаёт структуру и приоритеты, но не отменяет серверную безопасность,
доступность, аудит и существующие бизнес-инварианты.

В scope входят только существующий `PropertyCase`, его read model, действия,
вкладки, права и целевые проверки. Не входят кабинет инвестора, LandAsset,
пост-покупочные финансы, отдельный Deal, Collector и новые источники.

## Бизнес-правила

- Подтвердить покупку могут только `ProcurementHead` и `Owner`; менеджер не может
  выполнить операцию ни из UI, ни через API.
- Факт покупки содержит фактическую цену, дату и комментарий, завершает текущую
  задачу, но не создаёт автоматически сделку или актив.
- Ошибку в факте покупки исправляет пользователь с тем же отдельным правом.
  Причина обязательна; старые и новые значения сохраняются в timeline и audit.
- Рабочие факты не перезаписываются источником автоматически.
- Незавершённые проверки и риски показываются руководителю как готовность досье,
  но на этом Gate не становятся выдуманным автоматическим юридическим запретом.

- `dotnet build LandErp.slnx -c Release --no-restore`;
- целевые PostgreSQL-тесты прав покупки, корректировки и read model;
- проверка migration/model на расхождение, если доступна локальная PostgreSQL;
- `git diff --check`.

По прямому указанию владельца Playwright/браузерные тесты не запускаются.
Визуальная приёмка выполняется владельцем отдельно.
