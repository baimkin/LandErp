## Scope и файлы

- Общая форма CaseCommunication.razor/.css для CaseWorkspace и ProcurementQueueV2:
  «Записать общение», видимые способы связи, дата/HH:mm МСК, «С кем», один основной
  текст, три необязательные цены, видимая строка необязательной следующей задачи.
- ProcurementContracts, ProcurementWorkspace и ProcurementCaseTasks:
  существующие CaseNegotiation/WorkTask, одна транзакция и replay для пары,
  общие guards назначения/срока задачи, case version/visibility/organization.
- CaseCommunicationTests: существующие PostgreSQL fixtures.
- ACTIVE_TASK и reports/T_02_REPORT.md.

Новая команда использует существующую запись переговоров. Старый контракт/receipt
сохраняется. Новых таблиц/пакетов/миграций не планируется. Условия/комментарии старых
записей не меняются; пустые новые цены не очищают прежние. Существующего редактирования
общения нет; новая задача создаётся только при первом сохранении команды.
Вложения остаются существующим отдельным шагом после подтверждённой записи,
не входят в атомарность пары общение+задача и не вызывают её повторное создание.

## Проверки и завершение

Одна Release-сборка и узкие PostgreSQL-сценарии: без задачи; независимая задача
с date-only/точным сроком; replay/конкурентный дубль; rollback при недопустимом
исполнителе/сроке; версии, права, чужая организация, закрытый case; пустые цены.
Повтор только после исправлений/нового риска. Итог T_02_REPORT с фактическими
проверками и ручной приёмкой. Server/браузер/full suite/рабочая БД/публикация запрещены.
Ленты U-01, решения, проверки, рынок, Collector и следующие задачи вне scope.
