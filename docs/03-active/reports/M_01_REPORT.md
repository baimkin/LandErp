## Реализовано

- Одна организация-общая отметка `Listing.IncludeInCalculation`; начальное
  значение false, нет флагов по группам и переноса участников старой медианы.
- Команды отдельного изменения, предварительного просмотра и массового
  применения; сервер проверяет действующее Incoming.Process и организацию.
  Отдельная команда использует ожидаемую Version; повтор с актуальной версией
  и тем же значением не создаёт новую историю, устаревшая версия даёт конфликт.
- Таблица и массовый отбор используют `IncomingCatalogSelection`: прежние
  условия/OR/группы/поиск/срезы и нормализация архива F-02/F-03 вынесены из read
  service без альтернативной формулы. Pagination применяется только таблицей.
- Выбор нескольких строк текущей страницы либо всех результатов отбора,
  включая остальные страницы. Обновление страницы сбрасывает выбор строк.
  UI показывает число выбранных, затем серверный preview: будет изменено,
  уже имеют значение, не могут включаться, причины с количествами.
- Preview хранит только временный отпечаток состава ID/Version и направления.
  Apply повторно разрешает отбор, блокирует строки в порядке ID и сравнивает
  версии с preview. Изменившийся состав/версии не перезаписываются молча.
  Это подтверждение команды, не снимки/версии аналитических расчётов.
- В строке отдельно видны «Отметка включена/выключена», действие и пригодность.
  При включённой отметке и невалидных данных — «Временно непригодно» с причиной;
  такая строка не называется участвующей в расчёте. При валидных — «Данные пригодны».
  Сохранённая отметка при ухудшении цены/площади/валюты не снимается; при исправлении
  данных пригодность восстанавливается. Ручное выключение доступно в обоих случаях.
  Повторное включение отмеченной непригодной строки считается «уже имеет отметку»,
  не меняет данные и не создаёт событие; массовый preview считает аналогично.
- При первичном включении проверяется причина невозможности включения.
  Пригодность: цена > 0, площадь > 0, Currency == RUB; неизвестные не равны нулю.
- Duplicate/Fake/RemovedAtSource снимают отметку в существующих серверных
  командах. Возможный дубль не запрещает включение. Sold и Dismissed разрешены
  и сохраняют прежнее участие. Отдельное включение проданного проверено.
- В существующем разделении группы одного объекта добавлена выключенная
  галочка «Учитывать в расчёте медианы». Без неё участие не восстанавливается.
  Общего восстановления Fake/RemovedAtSource в текущем пути нет; новый процесс
  не добавлен. Автоматически выделенный представитель группы не включается.
- Настройка `AutoIncludeNewInCalculation` — необязательное поле JSON критериев
  с default false. Старые JSON без него читаются; условия F-01 сохраняются.
  Create/Update защищены прежней организацией/версией; добавлен append-only audit
  до/после условий и настройки. Нет backfill при изменении/выключении/удалении.
- Серверный ingress после сохранения новых Listing и observations, внутри той
  же незавершённой транзакции, проверяет OR применимых автоматических фильтров
  через общие Conditions и совместимость F-01. CompatibilityIssue пропускается.
  Изменяются исходные tracked Listing, а не read-проекции с AsNoTracking.
- Автоматизация получает только ID реально созданных в этом ingress Listing.
  Повтор доставки, новое наблюдение, смена цены существующего объявления и
  принадлежность к другой группе не дают повторного включения.
- Ручное создание тоже учитывает применимые фильтры. Групповых observations
  у него нет, поэтому групповой фильтр не подходит; привязки по адресу нет.
- Изменения отметок создают CatalogEvent и append-only audit: до/после, причина,
  пользователь или Collector agent, correlation ID. Новых пакетов/jobs нет.

Новая таблица и отдельные grants не требуются; команды выполнялись runtime ролью.

## Закрытое правило и ручная приёмка

Решение владельца 2026-09-26: при потере валидной цены/площади/валюты **сохранять
отметку**, временно считать данные непригодными и показывать причину. Исправление
данных возвращает пригодность без повторного включения. Если сотрудник снял
отметку, исправление данных её не восстанавливает. Дополнительные статусы,
фоновые задачи и механизм восстановления не добавлялись. Duplicate/Fake/
RemovedAtSource по-прежнему снимают отметку; Sold не исключается автоматически.
Вопрос согласования закрыт.

Для M-02 зафиксирован контракт: **фактический состав расчёта = сохранённая отметка
включена И данные пригодны** (`IncludeInCalculation && CalculationIneligibility == null`).
Сам расчёт M-02 не реализован.

Overview и старые настройки расчёта не менялись. Новые отметки ещё не управляют
показанными метриками — это M-02; в UI есть явное пояснение. M-03 и готовность
всего пакета не заявляются. Визуальная приёмка F-01–F-03/M-01 не выполнена.

После отдельно разрешённого применения миграции/запуска проверить вручную:

1. Состояние отметки и действия в строке; недоступность для исключающих состояний.
2. Несколько строк и все результаты на нескольких страницах; явное количество,
   причины отказа, конфликт при параллельном изменении, сброс выбора при обновлении.
3. Архив Sold/Dismissed и включение проданного; сохранённые фильтры/поиск/группы.
4. Настройку автофильтра, отсутствие backfill, новые поступления и ручное исключение.
5. Разделение группы с выключенной/включённой необязательной галочкой.
6. Включённая отметка при невалидных данных: подпись «Временно непригодно», причина
   и доступное выключение. После исправления данных пригодность возвращается,
   вручную выключенная отметка остаётся выключенной.
