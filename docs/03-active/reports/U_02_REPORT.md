## Поведение

- В полной карточке и панели очереди каждое непросмотренное изменение источника имеет отдельное кликабельное уведомление с источником и названием. Оно открывает окно поверх текущей страницы. Повторное открытие доступно через «Посмотреть изменения» в разделе «Источники» после исчезновения уведомления.
- В окне отображаются сохранённые изменения наблюдений: поле / было / стало, источник и время. Цена без копеек, описание с переносами, списки фото с подписями добавлений/удалений. Недоступное фото имеет явное состояние; остальные данные остаются доступны. Заголовок/закрытие доступны, длинное содержимое прокручивается внутри окна; на узком экране строки перестраиваются.
- Auto-ack вызывается после успешного открытия штатного dialog и отрисовки загруженного сравнения. Отдельной кнопки отметки нет. При ошибке чтения ack не вызывается. Если запись просмотра не удалась, сравнение остаётся открытым и доступен повтор сохранения просмотра.
- Закрытие окна повторно проверяет уведомления: изменения, пришедшие во время просмотра, остаются видимыми. Показанная старая версия не погашает новую. Повторное открытие и повторный ack безопасны.
- Просмотр не меняет рабочие факты, версию PropertyCase, состояние согласования или бизнес-рассмотрения источника. Существующие индикаторы необходимости бизнес-перерассмотрения остаются отдельными от новой отметки просмотра.

## Данные и точность

Сравнение использует `CatalogObservation.PayloadJson/ChangesJson`, а не рабочие факты PropertyCase. Read-scope закупки проверяется сервером, источник должен иметь подтверждённую связь с доступным объектом в той же организации. RepeatableRead фиксирует источник, его версию и наблюдения в одном состоянии БД.

Пропуски поля и пустой список фото не стирают прежнее известное значение. Позднее наблюдение не заменяет актуальные факты. Полнота истории проверяется по принятым версиям и крайним датам. Если прежнее значение неизвестно, выводится «Предыдущее значение не сохранено»; сравнение не восстанавливается из рабочей цены. Контакты при приёме добавляются, поэтому их прежний полный состав не выдумывается.

При отсутствии наблюдений сохранённые события цены могут дать независимо сохранённую пару до/после. Если данных недостаточно для отображения актуальной версии, `CanAcknowledge=false`: уведомление остаётся, окно объясняет отсутствие актуального сравнения. Повреждённый payload считается ошибкой чтения, а не пустым успешным результатом.

Фото основаны на сохранённых URL. Исторических копий байтов в этой модели нет: старый URL может стать недоступен, изменение изображения по тому же URL не определяется сравнением списков. В этом случае интерфейс не рисует фиктивное фото.

## Отметка просмотра и миграция

Использована **общая командная** отметка отдельно для каждой связи объект–источник: `PropertyCaseSourceLink.ViewedDataRevision`. Персональная таблица и новая система уведомлений не создавались.

`ReviewedDataRevision` и `SourcesChanged` не изменены: они по-прежнему участвуют в бизнес-решениях, запрете согласования новых данных и возобновлении объекта. Просмотр не является таким решением.

Миграция `20260927193208_SourceChangesViewedRevision` добавляет только `procurement.property_case_source_links.viewed_data_revision bigint NOT NULL DEFAULT 0` с комментарием. `0` означает отсутствие сохранённой отметки — ни прежнее бизнес-рассмотрение, ни существующая версия источника не копируются в это поле. Поэтому у ранее изменявшихся источников уведомления могут появиться снова: отсутствующая история просмотра не объявляется выполненной. Первая версия без изменений (`DataRevision=1`) сама по себе уведомления не создаёт.

Ack содержит конкретные CaseId, LinkId, CatalogItemId и показанную Revision. Сервер повторно проверяет read-доступ, организацию, активного сотрудника и подтверждённую связь; будущая версия отвергается. Атомарно записывается максимум существующей и показанной версии. Другая связь/источник не обновляется. Запоздалые ответы и конкурирующие окна не уменьшают отметку и не погашают версию, появившуюся позже показанной.

Миграция применена только к разрешённой `landerp_local`; применённые миграции не переписывались, данные не очищались. Runtime уже имеет UPDATE на существующую таблицу; новая таблица/роль/гранты не требуются. Проверка через runtime-сервис выполнена в PostgreSQL-тесте.
