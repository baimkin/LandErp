# Отчёт: упорядочивание незавершённой работы Parser

Дата: 18 сентября 2026 года. Ветка: `codex/parser-map-completion`.

## Результат

- Незавершённая работа отделена от старой ветки карточки объекта и перенесена на актуальный `main` выборочно.
- Server сообщает Parser четыре независимых счётчика: принято, без изменений, новых и обновлённых объявлений.
- Локальная очередь сохраняет подтверждённые Server счётчики и после безопасного повтора показывает тот же итог доставки.
- Старый Server остаётся совместимым: отсутствующие новые поля receipt читаются как нули.
- Для заданий карты рабочее окно показывает количество собранных и ожидаемых объявлений; обычные задания продолжают показывать страницы.
- Старые реализации очереди, URL-семантики и завершения карты не перенесены. Уже принятая актуальная логика `main` сохранена.

## Изменённые области

- Collector V1 contracts и Server Collector gateway.
- Parser Server outbox/coordinator и рабочее окно.
- Адресные Parser и PostgreSQL tests.

Новых пакетов и production migrations нет. Файлы B2 и указатель активной задачи не изменялись.

## Проверки

- Release build всего решения: успешно, 0 предупреждений и 0 ошибок.
- Parser receipt/outbox tests: 2/2 успешно.
- PostgreSQL Collection gateway test новых счётчиков: 1/1 успешно.
- Большой HTTPS end-to-end test не дошёл до проверяемой логики: изолированный тестовый Server завершился при старте; повторный контроль упёрся в уже запущенный пользовательский Server. Это не подменяется успешным результатом.
- `git diff --check`: успешно; только уведомления Git о локальном преобразовании LF/CRLF.

## Ручная проверка

После обновления и перезапуска Server можно выполнить серверное задание Parser и проверить строку результата доставки: собранные, принятые, дубли, новые и обновлённые объявления. Для карты прогресс должен отображаться в объявлениях.
