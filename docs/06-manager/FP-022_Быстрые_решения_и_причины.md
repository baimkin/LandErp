# FP-022 — Быстрые решения и причины

**Версия:** 0.1  
**Статус:** Черновик  
**Модули:** ManagerWorkspace  
**Зависимости:** FP-020, FP-021

## 1. Результат

Менеджер за несколько действий выбирает `В работу`, `Наблюдать`, `Уточнить` или
`Отклонить`, а система сохраняет понятную причину, версию исходных данных и
следующий шаг. Решение доступно из очереди и карточки одинаково.

## 2. Правила решений

- `В работу`: ответственный и следующий шаг обязательны.
- `Наблюдать`: обязательны дата, цена либо событие возврата.
- `Уточнить`: создаётся вопрос/задача с владельцем.
- `Отклонить`: выбирается стабильный код причины; комментарий обязателен для
  `Другое` и рискованных причин.

Причины управляются как версионируемый справочник. Старое решение сохраняет
текст на момент выбора. Удаление причины запрещает новый выбор, но не портит
историю.

## 3. UX

Основные действия доступны клавиатурой; опасное отклонение легко отменить в
коротком окне через компенсирующее действие. Массовые решения не входят в первую
версию. UI показывает, какое наблюдение и цена лежат в основе решения.

## 4. Данные и API

`Decision` неизменяем: target, action, reason, note, actor, timestamp, source
observation/version. Исправление создаёт новое решение, связанное с отменённым.
Команда имеет idempotency key и concurrency token QueueItem.

## 5. Контроль качества

Система не рекомендует отклонение при низком качестве извлечения. Причина
`Ошибка данных` направляет сигнал в FP-014, а не ухудшает оценку участка.

## 6. Тесты и DoD

- обязательные поля каждого действия;
- двойной клик не создаёт два решения;
- конфликт версий не затирает чужую работу;
- скрытая причина остаётся в истории;
- отмена создаёт аудит;
- права Manager/Lead/Admin и отсутствие Investor access;
- четыре решения одинаково работают из очереди и карточки.

## 7. Открытые вопросы

- начальный справочник причин;
- допустимо ли короткое undo после отклонения;
- какие решения доступны руководителю от имени менеджера;
- потребуется ли массовая обработка после измерения пилота.
