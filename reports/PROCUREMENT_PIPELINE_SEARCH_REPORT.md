## Решения

1. Компактная строка над результатами выбранной воронки, общая для таблицы и
   канбана. Поиск после паузы 350 мс, Enter — без задержки, отдельный сброс только
   текста. Текущий запрос сохраняется при переключении представления.
2. Один серверный предикат для общей очереди, таблицы воронки и доски: адрес,
   название, номер PC, КН, контакт переговоров, подтверждённые источники
   (название/внешний номер/продавец), точный UUID объекта/источника. Сохранены
   регистронезависимое вхождение и Trim существующего поиска.
3. Поиск пересекается с разрешённым набором объектов, выбранной воронкой и
   менеджером до пагинации и агрегатов; роли и scope доступа не менялись.
   Связанные контакты/источники дополнительно ограничены организацией объекта.
4. «Ещё» передаёт тот же запрос; новый запрос заново читает все колонки с первой
   части. Счётчики/суммы/скрытые стадии считаются по найденному набору.
5. При фильтрации таблицы поисковый подзапрос читает только факты объектов
   своей организации; авторизованная внешняя выборка сохраняет scope/воронку.
   Не дублируется выбор ближайшей задачи внутри поискового подзапроса.
6. Предыдущий отложенный ввод отменяется; новый ждёт текущего чтения/переноса,
   чтобы существующая защита ReloadAsync от параллельных чтений не теряла ввод.
   При уничтожении страницы ожидание отменяется. Старые контракты чтения доски
   сохранены как перегрузки с пустым запросом.
7. Прежнее решение скрывать поиск в KANBAN_PLAN явно отменено текущим запросом.
   Остальные фильтры общей очереди в воронке не активируются.
