# TP-010 — Первая фикстура поисковой выдачи Авито

**Статус:** Старый scope первого адаптера устарел; reuse tests в Collector, не активен\

> Ревизия 2026-09-14: Reuse sanitised fixtures/provenance/negative checks; классификация/выдача уже реализованы в Spike, не писать parser заново для Server.
> [ERP-00 report](../03-active/reports/ERP-00_REPORT.md) — итоговая ревизия.
> Примеры ниже — исторический материал, не approved implementation. Текущий
> scope задаёт ACTIVE_TASK; ни этот TP, ни старые зависимости не разрешают код.
**Зависимости:** TP-009, FP-012, ADR-005  
**Результат:** Agent без выхода в production-сбор классифицирует приложенный HTML выдачи и извлекает проверяемый набор карточек.

## Входит

- сохранённый HTML как sanitised test fixture;
- `IListingSourceAdapter` и реализация `AvitoSourceAdapter` внутри Agent;
- классификация `SearchResults`, `AuthenticationRequired`, `Captcha`, `Unknown`;
- извлечение только основного контейнера;
- external ID, URL, title, raw/parsed price, raw/parsed area, location, preview;
- presence/provenance и completeness report;
- fixture contract tests;
- payload версии `SearchPageResultV1`.

Live navigation, detail page, фото, телефон, сообщения и production schedule не входят.

## Эталон результата поля

```csharp
public enum FieldPresence
{
    Present,
    Absent,
    Empty,
    ParseFailed,
    NotInspected
}

public sealed record ExtractedField<T>(
    string? Raw,
    T? Parsed,
    FieldPresence Presence,
    string Origin);
```

## Эталон классификации

```csharp
public enum SourcePageKind
{
    SearchResults,
    ListingDetails,
    AuthenticationRequired,
    Captcha,
    RateLimited,
    SourceError,
    Unknown
}
```

Классификация выполняется до извлечения. `Unknown` не возвращает пустой успешный список.

## Контрольный набор

- число карточек основного контейнера задаётся ожидаемым fixture-result;
- рекомендационные/чужие блоки не становятся Listing;
- карточка без external ID фиксируется extraction error;
- цена и площадь сохраняют raw даже при ParseFailed;
- относительная дата не превращается в точное время без правила;
- fixture не содержит cookies, токены, переписку и лишние персональные данные.

## Проверки

- повторный разбор детерминирован;
- изменение selector, уменьшающее полноту, ломает contract test;
- Captcha/Unknown fixture возвращают AttentionRequired;
- DTO сериализуется согласно AgentContracts;
- payload ограничен по размеру и не содержит полный HTML.

## Definition of Done

Fixture выдачи даёт ожидаемые карточки и quality report; ни одно неизвестное или
пустое состояние не интерпретируется как массовое снятие объявлений.
