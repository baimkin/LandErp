# Инструкция для Zoo Code и DeepSeek

Этот каталог содержит обязательный визуальный и поведенческий эталон интерфейса LandErp.

## Перед каждой задачей по интерфейсу

1. Прочитай этот файл.
2. Изучи `ui-kit/tokens.css`.
3. Найди в `ui-kit/index.html` наиболее близкий экран или компонент.
4. Проверь его стили в `ui-kit/styles.css` и поведение в `ui-kit/app.js`.
5. До изменения общих токенов или визуальных правил запроси одобрение пользователя.

## Обязательные правила реализации

- Основной стек: C#, .NET, Blazor и локальный CSS проекта.
- Переноси интерфейс в переиспользуемые Razor-компоненты, а не вставляй демонстрационный HTML целиком.
- Разрешено использовать уже утверждённый локальный Bootstrap CSS как базовую сетку, utilities и основу форм согласно ADR-006/FP-003. Не подключай и не обновляй Bootstrap самостоятельно, не используй Bootstrap JS и не добавляй Tailwind, Material UI, JavaScript-фреймворки, внешние шрифты, CDN или пакеты компонентов без отдельного согласования.
- JavaScript применяй только там, где возможностей Blazor недостаточно; изолируй JS interop по компонентам.
- Не копируй значения цветов, отступов и размеров в компоненты: используй CSS custom properties из дизайн-токенов.
- Сохраняй два режима интерфейса: плотный рабочий режим ERP и более спокойный кабинет инвестора.
- Цвет не должен быть единственным носителем смысла: статус сопровождай текстом или понятным значком.
- Для загрузки, отсутствия данных, ошибки, запрета доступа и устаревших данных предусматривай явные состояния.
- Все формы должны иметь label, сообщения проверки и понятное состояние disabled.
- Таблицы должны поддерживать длинные значения, пустые поля, сортировку, фильтрацию, выбор строк и постраничность там, где это требуется сценарием.
- Используй системный стек шрифтов из `tokens.css`; не загружай внешние шрифты.
- Не меняй общий визуальный язык ради одной страницы. Если компонента не хватает, сначала предложи расширение UI-kit.

## Предлагаемая структура Blazor-компонентов

```text
Components/
  Primitives/       кнопки, поля, значки, статусы, подсказки
  Feedback/         уведомления, ошибки, skeleton, empty state
  Navigation/       боковое меню, breadcrumbs, вкладки, пагинация
  DataDisplay/      таблицы, KPI, карточки, timeline, price history
  Overlays/         dialog, drawer, confirmation
  Domain/           ListingCard, PropertyFacts, DueDiligenceChecklist
                     ProjectEconomics, ParserAgentStatus, InvestorSummary
Layout/
  ErpLayout.razor
  InvestorLayout.razor
wwwroot/css/
  tokens.css
  components.css
  pages.css
```

Это ориентир, а не разрешение создавать все компоненты заранее. Компонент добавляется, когда он нужен конкретной функции и имеет понятный контракт.

## Критерии готовности интерфейсной задачи

- экран соответствует UI-kit по цветам, типографике, отступам, плотности и состояниям;
- нет новых внешних зависимостей без одобрения;
- повторяющиеся элементы вынесены в компоненты;
- проверены desktop, узкий desktop/tablet и mobile;
- управление доступно с клавиатуры, фокус видим, у интерактивных элементов есть доступные названия;
- loading, empty, error, forbidden и disabled не забыты;
- данные и действия скрываются или запрещаются в соответствии с ролью пользователя;
- бизнес-правила не размещены внутри визуальных компонентов;
- тесты добавлены на значимое поведение, а не на декоративную разметку.

## Готовый префикс задания агенту

> Реализуй задачу в LandErp. Перед началом изучи `docs/ui-kit/AGENT_UI_INSTRUCTIONS.md`, `docs/ui-kit/ui-kit/tokens.css` и соответствующий пример в `docs/ui-kit/ui-kit/index.html`. UI-kit является обязательным визуальным эталоном. Используй Blazor и существующие средства проекта. Не добавляй внешние UI-пакеты и не меняй дизайн-токены без моего одобрения. Сначала перечисли затрагиваемые файлы и краткий план, затем дождись разрешения на запись.

## Важно

Файлы в `ui-kit/` — интерактивный прототип и источник правил, но не готовая архитектура приложения. Бизнес-логика, авторизация, API, хранение данных и права доступа реализуются в соответствующих слоях LandErp.
