# OP-010 — Установка и обновление локального агента

**Версия:** 0.2  
**Статус:** Черновик  
**Владелец:** администратор сбора  
**Зависимости:** ADR-001, ADR-004, FP-011, OP-002

## 1. Результат

Администратор безопасно подключает 3–5 компьютеров, видит их версии и состояние,
поэтапно обновляет Agent без потери локального outbox и может отозвать устройство.

## 2. Установка

Первая поддерживаемая и проверяемая платформа — Windows x64. Пакет должен
работать на обычной рабочей станции без постоянных административных прав. Код
сохраняет переносимость, но установщики и эксплуатационные инструкции для
Linux/macOS не входят в первый релиз.

1. Проверить поддерживаемую ОС, свободное место, доступ к Server HTTPS и браузер.
2. Скачать только утверждённый пакет, проверить подпись/hash и версию.
3. Установить Agent под отдельной локальной учётной записью с минимумом прав.
4. Создать на сервере одноразовый registration code с коротким сроком.
5. Зарегистрировать устройство, задать понятное имя и проверить capabilities.
6. Выполнить диагностическое задание без бизнес-изменений.
7. Разрешить один тестовый поиск, затем включить устройство в общий пул.

Agent не получает connection string БД, серверные секреты или общий ключ других
машин. Профиль браузера и сессия источника остаются локальными.

## 3. Локальные данные

Отдельно хранятся конфигурация соединения, защищённый credential, браузерный
профиль, SQLite outbox и диагностические логи. Удаление/переустановка не начинается,
пока outbox не пуст или не принято явное решение о его сохранении. Логи имеют
ограниченный срок и не содержат cookies, токены и полный HTML по умолчанию.

## 4. Режим работы

Поддерживаются интерактивный запуск и утверждённый фоновый режим. Agent показывает
`Online/Idle/Busy/Paused/Draining/AttentionRequired/Revoked`, текущую задачу,
последний heartbeat и число записей outbox. Пользователь не меняет серверное
расписание локально.

## 5. Обновление

- Server публикует минимальную и рекомендуемую версии.
- Обновление сначала ставится на одну тестовую машину.
- Перед остановкой Agent переходит в `Draining`, завершает безопасный шаг и
  отправляет outbox.
- Пакет проверяется до замены файлов; конфигурация и outbox сохраняются.
- После запуска выполняются heartbeat, contract check и диагностическая задача.
- Затем обновляются остальные машины по одной.

Автообновление откладывается до появления подписанного канала и проверенного
rollback. На старте используется контролируемая ручная установка.

## 6. Сбой и откат

При несовместимости новая версия не получает задания. Администратор возвращает
предыдущий утверждённый пакет, не откатывая формат outbox без миграционного плана.
Повреждение credential решается отзывом и новой регистрацией, а не копированием
секрета с другой машины.

## 7. Безопасность

- запуск без административных прав после установки;
- allowlist серверных адресов и обязательный TLS;
- уникальный отзываемый credential;
- запрет входящих портов/удалённых команд общего назначения;
- аудит регистрации, rotation, версии, pause/drain/revoke;
- браузер источника не используется для личной работы сотрудника.

## 8. Проверки

- чистая установка и повторная регистрация;
- перезапуск с непустым outbox;
- обновление на одну версию вперёд и rollback;
- запрет старой/отозванной версии;
- сохранение профиля и конфигурации;
- отсутствие двойной обработки после crash;
- работа на каждой утверждённой ОС.

## 9. Definition of Done

- инструкция проверена на фактических компьютерах;
- пакет идентифицируем и проверяется;
- одна машина обновляется без потери результата;
- сервер показывает версии и совместимость;
- revoke немедленно прекращает новые lease;
- есть короткая памятка оператору.

## 10. Открытые вопросы

- способ фонового запуска в Windows: пользовательский процесс или Windows Service;
- каталог установки и политика прав;
- доверенный канал доставки пакета;
- допустимое окно обновления.
