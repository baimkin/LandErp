# FP-012 — Парсинг Авито: выдача и подробная карточка

**Версия:** 0.1  
**Статус:** Черновик  
**Владелец:** владелец продукта / администратор сбора  
**Модуль и приложение:** Collection + LandErp.Agent  
**Зависимости:** FP-010, FP-011, ADR-004, политика допустимого доступа к источнику  
**Блокирует:** FP-013, FP-014, FP-020

## 1. Решение

Реализовать первый source adapter для Авито с двумя независимыми типами задания:
сбор основного контейнера поисковой выдачи и сбор подробной карточки объявления.
Адаптер работает через Microsoft.Playwright в локальном Agent, распознаёт тип
страницы, извлекает исходные значения с признаком присутствия и диагностикой,
нормализует только однозначные форматы и возвращает версионированный результат.
Система не обходит CAPTCHA и не считает пустую/неизвестную страницу снятием всех
объявлений.

## 2. Ценность

- новые предложения обнаруживаются без ручного просмотра 30–50 ссылок;
- подробный проход запускается отдельно и не тормозит свежую выдачу;
- каждое значение имеет происхождение и уровень сбора;
- изменение разметки проявляется как измеряемая ошибка качества;
- менеджер получает реальные карточки, а не необъяснимый массив HTML;
- адаптер можно заменить без переделки домена ERP.

## 3. Предусловие допустимости

Перед production-включением владелец процесса подтверждает допустимый способ
работы с источником по актуальным условиям и фактическому сценарию. План не
предполагает обход технических ограничений, скрытие автоматизации, CAPTCHA solving
или использование украденных/чужих сессий.

При отсутствии допустимого автоматизированного канала остаются ручное добавление
по ссылке и разрешённый импорт.

## 4. Границы

### Входит

- распознавание страницы выдачи, карточки, CAPTCHA/auth/error/unknown;
- навигация по сохранённому URL;
- извлечение только основного контейнера выдачи;
- отделение рекомендаций и других регионов;
- проход страниц/ленты в утверждённых лимитах;
- извлечение summary-полей;
- открытие прямой карточки отдельным заданием;
- извлечение detail-полей и фотографий как URL/метаданных по политике;
- сохранение исходного текста значений;
- нормализация цены, площади и дат только при однозначности;
- диагностические коды и completeness;
- HTML-фикстуры и контрактные тесты;
- скриншот/trace только при разрешённых диагностических условиях.

### Не входит

- автоматическая отправка сообщений;
- показ телефона;
- массовая загрузка всех оригиналов фотографий;
- юридический вывод по описанию;
- автоматическое объединение объявлений в PropertyCase;
- обход CAPTCHA/банов;
- второй источник;
- изменение фильтров поиска;
- headless как обязательный режим без проверки устойчивости.

## 5. Типы страниц

| Тип | Признаки | Результат |
|---|---|---|
| SearchResults | Основной контейнер результатов и поисковый контекст | SearchPageResult |
| ListingDetails | ID/заголовок/карточка объекта | ListingDetailsResult |
| AuthenticationRequired | Форма или явный запрос входа | AttentionRequired |
| Captcha | Признаки CAPTCHA/проверки человека | AttentionRequired |
| RateLimited | Явное ограничение/служебная страница | Retry/Attention по политике |
| ListingUnavailable | Явное состояние конкретной карточки | Detail outcome, не массовое событие |
| SourceError | Явная ошибка источника | Temporary/Permanent по коду |
| Unknown | Нет известных надёжных признаков | AttentionRequired + диагностика |

Классификация выполняется до извлечения бизнес-полей.

## 6. Уровень 1 — поисковая выдача

### 6.1. Основная задача

Быстро обнаружить новые external ID и изменения основных полей. Результат
содержит только карточки из подтверждённого основного контейнера выдачи.

### 6.2. Поля карточки выдачи

- source code;
- external listing ID;
- canonical/direct URL;
- заголовок;
- цена и исходный текст цены;
- цена за сотку, если площадка явно показывает её;
- площадь и исходный текст;
- категория/назначение из видимой карточки;
- адрес/локация;
- опубликованная/относительная дата как исходный текст;
- краткое описание;
- имя/тип продавца, если присутствуют;
- badges и видимые признаки;
- preview image URL/metadata;
- позиция в основном контейнере;
- номер страницы/cursor;
- origin block: main result или иной распознанный блок.

### 6.3. Правила выдачи

- Счётчик «найдено N» сохраняется как page metadata, но не равен parsed count.
- Карточки рекомендаций не входят в основной результат и могут сохраняться только
  отдельным диагностическим набором без создания Listing.
- Сортировка «по дате» не позволяет остановиться на первом известном ID.
- Используется перекрытие страниц/порога известных ID и контрольная сверка.
- Дубликат ID на нескольких страницах сохраняет несколько SearchMatch, но один
  кандидат результата.
- Отсутствующий ID является extraction error карточки, а не поводом придумать ключ
  из заголовка и цены.
- Число обработанных, пропущенных и ошибочных DOM-карточек возвращается отдельно.

## 7. Уровень 2 — подробная карточка

### 7.1. Основная задача

Получить наиболее полное наблюдение нового, изменившегося или интересного
объявления по прямому URL.

### 7.2. Поля подробной карточки

- external ID и canonical URL;
- заголовок;
- полная цена и отображаемая цена за единицу;
- площадь;
- категория земли/назначение из структурированных параметров;
- полный адрес и видимая локация;
- координаты, только если надёжно извлечены;
- полное описание;
- структурированные характеристики как именованные исходные пары;
- кадастровые номера, как заявленные значения;
- сведения о продавце и типе профиля;
- доступные способы связи без раскрытия телефона в первой версии;
- badges/верификации площадки;
- дата публикации/изменения, если явно доступна;
- список photo metadata;
- явное состояние доступности;
- сырой JSON/metadata конкретной версии адаптера по политике;
- диагностика наличия каждого ожидаемого блока.

### 7.3. Правила подробной карточки

- Значение «ИЖС» в заголовке и «ЛПХ» в описании сохраняются как два утверждения и
  создают contradiction marker.
- Площадь 8,4 в параметрах и 8,37 в описании не усредняется и не округляется в
  «подтверждённый факт».
- Кадастровый номер из текста считается заявлением источника, не официальной
  кадастровой проверкой.
- Координата без подтверждённого происхождения получает уровень качества и не
  считается границей участка.
- Отсутствие detail-поля не очищает прежнее значение автоматически.

## 8. Извлечение и нормализация

### 8.1. Три слоя значения

1. Raw — как показано источником.
2. Parsed — типизированный результат однозначного разбора.
3. Assertion/Conclusion — последующая оценка домена или специалиста, не задача adapter.

### 8.2. Поле с присутствием

Adapter различает:

- Present — блок был и значение извлечено;
- Absent — блок достоверно отсутствовал в распознанной странице;
- Empty — блок присутствовал без значения;
- ParseFailed — значение было, но типизация не удалась;
- NotInspected — этот уровень/версия не проверял поле.

Это предотвращает удаление detail-данных снимком выдачи.

### 8.3. Числа и единицы

- Цена парсится в decimal и валюту, если формат однозначен.
- Площадь парсится вместе с единицей; сотки и квадратные метры не смешиваются.
- Цена за сотку от площадки хранится отдельно от вычисленной системой.
- Относительная дата сохраняет raw text и вычисляется с observed time/timezone;
  неоднозначность помечается.
- Любое округление имеет код правила adapter version.

## 9. Навигация браузера

- Использовать устойчивые user-facing/semantic locators, где возможно.
- CSS/XPath-селекторы изолированы внутри adapter version.
- Не полагаться на произвольный `Task.Delay` вместо ожидания наблюдаемого состояния.
- У навигации есть timeout и классификация результата.
- Случайный pop-up/баннер обрабатывается только по известному безопасному сценарию.
- Перед каждым действием проверяется page classification.
- BrowserContext изолирован по утверждённой политике профиля.
- Trace/screenshot включаются по диагностической политике, а не постоянно без лимита.

## 10. Контракт результата выдачи

Результат содержит:

- SourceCode и AdapterVersion;
- SearchDefinitionId, SearchRevisionId, SearchRunId;
- RequestedUrl и FinalUrl;
- ObservedAt;
- PageClassification;
- SortModeObserved;
- ReportedTotal;
- ParsedMainCount;
- SkippedMainCount;
- OtherBlockCount;
- карточки;
- warnings/errors;
- completeness metrics;
- navigation metadata;
- content hash/diagnostic artifact references.

## 11. Контракт результата карточки

- SourceCode, ExternalId, AdapterVersion;
- RequestedUrl, FinalUrl;
- ObservedAt;
- PageClassification и AvailabilityOutcome;
- типизированные поля с presence/raw/parsed;
- named raw attributes;
- photo metadata;
- contradictions detected внутри источника;
- completeness и extraction errors;
- безопасные диагностические ссылки.

## 13. Контроль качества

### Completeness

Обязательные поля уровня выдачи для пилота:

- external ID;
- direct URL;
- title;
- price state;
- position/origin.

Площадь и локация важны, но их отсутствие не всегда означает ошибку всей страницы.
Порог остановки источника определяется FP-014 на контрольном наборе.

### Аномалии

- parsed main count резко равен нулю при известной активной выдаче;
- reported total значительно отличается от фактически доступного числа без
  объяснимой пагинации;
- доля карточек без external ID выше порога;
- изменился PageClassification;
- выросло число ParseFailed;
- много final URL другого региона;
- adapter version даёт другой результат на неизменной фикстуре.

## 14. Диагностика и приватность

- По умолчанию сохраняется структурная диагностика, не полный HTML.
- Полный HTML/trace/screenshot — только при ошибке, ограниченном размере, сроке
  хранения и доступе администратора.
- Cookies, auth headers, сообщения и персональные поля маскируются.
- Diagnostic artifact имеет TaskId, adapter version, hash и expiry.
- Просмотр и скачивание чувствительной диагностики аудируются.

## 15. Ошибки

| Ситуация | Результат |
|---|---|
| CAPTCHA | AttentionRequired; extraction не продолжается |
| Login page | AuthenticationRequired |
| Unknown page | PageStructureUnknown + диагностика |
| Один элемент сломан | Остальные возвращаются; item error учитывается |
| Основной контейнер не найден | Ошибка страницы, не пустая успешная выдача |
| Detail unavailable явно | ListingUnavailable observation |
| Навигационный timeout | SourceTemporary или AgentInternal по диагностике |
| URL ушёл на другой host | Permanent/security error |
| Нет external ID | Карточка пропущена с ошибкой; synthetic ID не создаётся |

## 16. Contract fixtures

Минимальный набор:

- первый экран выдачи с основной лентой;
- выдача с рекомендациями других городов;
- следующая страница/прокрутка;
- одинаковый ID в пересекающихся проходах;
- карточка частного продавца;
- карточка агентства;
- расхождение площади 8,4/8,37;
- противоречие ИЖС/ЛПХ;
- снятое объявление;
- страница login;
- CAPTCHA;
- source error;
- пустой основной контейнер;
- неизвестная изменённая разметка.

Каждая fixture имеет provenance, дату, ожидаемую classification и ожидаемые поля.
Секреты и активные session data удалены.

## 17. Наблюдаемость

Метрики:

- page classification;
- navigation/extraction duration;
- parsed/skipped counts;
- completeness по полям;
- parse failed rate;
- CAPTCHA/auth/rate limit;
- adapter version;
- detail success by listing type;
- diagnostic artifacts created/expired.

Логи не содержат полный description и cookies.

## 18. Тестирование

| Уровень | Обязательные случаи |
|---|---|
| Unit | price/area/date parse, URL extraction, presence state, contradiction detection |
| Contract | все fixtures раздела 16 и стабильный snapshot результата |
| Browser integration | реальная навигация на разрешённом тестовом контуре/сохранённой странице |
| Agent contract | сериализация двух уровней и совместимость версий |
| Resilience | timeout, закрытие browser, повтор Task, частичный item failure |
| Security | redirect host, oversized content, недоверенный HTML, маскирование диагностики |
| Acceptance | ручное сравнение 30–50 карточек контрольной выдачи |

## 19. Вертикальные этапы

1. Page classifier и contract tests на fixtures.
2. Один SearchResults Task извлекает первую страницу и возвращает structured result.
3. Выдача проходит страницы в безопасном лимите и отделяет другие блоки.
4. Один ListingDetails Task извлекает подробные поля.
5. Добавляются presence, completeness, contradictions и diagnostic policy.
6. Выполняется ручная контрольная сверка и исправляется каждый класс пропуска.
7. Adapter включается для одного реального поиска под наблюдением.

## 20. Развёртывание

- Adapter version входит в Agent artifact и результат.
- Новая версия сначала запускается на одном Agent и контрольном поиске.
- Feature flag позволяет отключить конкретную версию/source.
- Предыдущая версия может временно оставаться доступной для сравнения fixtures,
  но не выполняет параллельный production-сбор без разрешения.
- Массовое падение completeness автоматически останавливает новые задания.

## 21. Definition of Ready

- подтверждён допустимый способ работы с Авито;
- утверждены типы заданий FP-011;
- предоставлены актуальные обезличенные HTML fixtures;
- согласованы поля выдачи и карточки;
- определены лимиты страниц/времени/диагностики;
- согласована политика browser profile;
- определены критерии CAPTCHA/auth/unknown;
- готово хранение результата FP-013 хотя бы в пилотном контракте.

## 22. Definition of Done

- выдача и карточка являются разными Task и результатами;
- adapter не создаёт synthetic ID;
- рекомендации/другие города не смешиваются с основным результатом;
- счётчик сайта не используется как parsed count;
- Sort by date не вызывает раннюю остановку на первом известном ID;
- raw/parsed/presence сохраняются;
- противоречия не превращаются в придуманный факт;
- CAPTCHA/auth/unknown ведут в AttentionRequired;
- fixtures и контрольная выборка проходят согласованный порог;
- диагностика ограничена и безопасна;
- Agent и Server contract tests зелёные.
