## Результат

В списке входящих добавлены номера страниц, текущая страница/общее количество,
переходы в начало/конец и сохранены назад/вперёд. До девяти страниц показываются
все номера, для длинной выдачи — первая/последняя и окно около текущей с многоточиями.
Размер страницы выбирается из 25 / 50 / 100 (25 по умолчанию); смена размера
открывает первую страницу, сохраняет условия, сортировку и выбранные объявления.

Пустая последняя страница после массового архива или изменения результатов
автоматически заменяется последней доступной; для пустого результата нет
некорректного диапазона. Контролы отключаются во время загрузки/записи и на границах.
Панель переносится по ширине workspace, использует существующие CSS tokens.

## Решения

- Переиспользованы существующие `Offset` / `Size` и серверная стабильная сортировка;
  новых запросов к БД на каждую строку нет, backend/schema не менялись.
- Для идентичности массового отбора нормализуются и смещение, и размер страницы:
  изменение видимой порции не очищает выбор и исключения режима «все».
- После чтения проверяется существование страницы; при сокращении результатов
  выполняется один дополнительный запрос на последнюю допустимую страницу.
- Прямой переход проверяет границы; недопустимые размеры страницы игнорируются.
- Сохранение размера после перезагрузки сайта не добавлялось.

Проверки настоящей Razor-страницы выполняются через `HtmlRenderer`, без JS,
с изолированной PostgreSQL. Production, рабочая БД и работающий сервер не изменены.
Парсеры, пакеты и migrations не затрагивались. На этапе реализации commit/push и развёртывание не выполнялись.

После отдельного обновления приложения владельцу проверить навигацию, размеры
страниц, перенос панели на узкой ширине и массовый архив с выделением между
страницами. Следующая задача автоматически не активируется.
