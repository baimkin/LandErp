Collector читает прежний `markers.drawAreaBase64` и `pins.success.drawArea`.
Для pins поддержаны JSON и Base64 с JSON. Из результата берутся только
допустимые полигоны. Область видимости карты и метки не служат геометрией.
Сопоставление зоны, фильтров и координат карточек выполняет прежняя проверка.
Если оба формата вернули разные полигоны, контур недоступен для приёма новых
карточек и в предупреждениях появляется MAP_DRAW_SOURCE_CONFLICT.
Диагностический режим для drawArea сохраняет итог декодирования и число
валидных полигонов без исходной строки.

отбрасывание неподходящего формата и доставку pins через обработчик IPage.

## Причина отклонения контура

Снимок 13:11 МСК показал DecodedJson, PolygonCount=0 и одно кольцо из
133 пар чисел. MapDiagnosticCapture теперь пишет Rejection из
SearchAreaGeometry.Read. Используется та же последовательность проверок,
что в обычном сборе. Код различает неподдерживаемую структуру, неверные
точки, незамкнутое кольцо, повтор вершины, самопересечение и другие
условия валидации. Значения координат в Rejection отсутствуют.

Затронуты SearchAreaGeometry.cs, MapDiagnosticCapture.cs и
MapDiagnosticTests.cs. Добавлены проверки открытого кольца, повторной
вершины, пересечения и валидного контура. Release build тестового проекта
с --no-restore собрал Desktop, Collector и тесты без ошибок и предупреждений.
Адресный тест drawArea/pins/markers: 12/12. Широкий набор: 197/200.
Нагрузочный SQLite тест сообщил «database or disk is full», ещё два теста
с рабочими БД упали в этом же прогоне. TRX в
artifacts/parser-drawarea-rejection/tests/drawarea-rejection-acceptance.trx.
Подготовлены только собственные DLL/PDB из протестированной Release сборки,
чтобы избежать полного копирования на диск с малым свободным местом.
