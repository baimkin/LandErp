# Управление контекстом и передача задачи

## 1. Файлы состояния в будущем репозитории

Рекомендуется вести:

- `docs/status/CURRENT_TASK.md` — только текущая задача;
- `docs/status/IMPLEMENTATION_LOG.md` — краткая хронология;
- `docs/status/OPEN_QUESTIONS.md` — нерешённые вопросы с владельцами;
- `docs/status/TECHNICAL_DEBT.md` — долг с условием возврата;
- `docs/status/RELEASE_NOTES.md` — пользовательские изменения.

Они не заменяют Git, ADR и `TP`.

## 2. Шаблон CURRENT_TASK

```markdown
# Текущая задача

- TP: TP-NNN
- Статус: анализ / реализация / проверка / заблокировано
- Цель:
- Уже сделано:
- Изменённые файлы:
- Выполненные проверки:
- Не выполнено:
- Следующий безопасный шаг:
- Решения владельца, полученные в ходе задачи:
```

## 3. Handoff при новом диалоге

Перед завершением контекста Zoo Code должен подготовить не более одной страницы:

1. исходная цель;
2. подтверждённые решения;
3. фактически изменённые файлы;
4. прошедшие/непрошедшие команды;
5. незавершённые действия;
6. известные риски;
7. точный следующий шаг.

Запрещено писать «всё почти готово» без перечисления оставшегося.
