# Маршрут согласования пакета Land ERP

**Версия:** 0.3  
**Назначение:** просмотреть большой пакет без необходимости читать всё подряд

## 1. Что уже можно принять как направление

Сначала прочитать генеральный план и журнал решений. Если общая логика верна,
не нужно одновременно согласовывать все числовые настройки. Достаточно отмечать:
`принять`, `изменить`, `отложить`.

## 2. Фундаментальные решения — приняты 6 сентября 2026 года

| Порядок | Документ | Принятое решение |
|---:|---|---|
| 1 | ADR-001 | .NET 10 LTS; Windows x64 как первый Agent |
| 2 | ADR-002 | модульный монолит; solution/namespace `LandErp` |
| 3 | ADR-003 | PostgreSQL-очередь для 30–50 ссылок и 3–5 Agent |
| 4 | ADR-004 | вход по приглашениям, MFA и отдельный credential Agent |
| 5 | ADR-005 | внешний backend через `IFileStorage`, метаданные в PostgreSQL |
| 6 | ADR-006 | локальный Bootstrap CSS, собственные компоненты, минимум зависимостей |

Конкретные провайдеры, сроки хранения и числовые параметры уточняются в
bootstrap/операционных задачах без повторного открытия принятых принципов.

## 3. Первый рабочий контур

Читать в порядке:

1. `FP-001`, `FP-002`, `FP-003` — каркас, доступ, визуальный стиль.
2. `FP-010` → `FP-011` → `FP-012` → `FP-013` — ссылка, задание, парсинг, каталог.
3. `FP-014`, `FP-015` — защита от неверных данных и мониторинг.
4. `FP-020` — что получает менеджер.
5. `OP-001`, `OP-002`, `OP-003`, `OP-010`, `OP-011` — как запускать и поддерживать.

После согласования из этих документов создаются только ближайшие `TP`: одна
поисковая ссылка, один Agent, одна страница выдачи и одна карточка.

Стартовые `TP-001`–`TP-010` уже подготовлены в
`LandErp_Development_Starter_Pack/TaskPlans`. Их следует просматривать по одному;
статус `На согласовании` не разрешает Zoo Code изменять код.

## 4. Бизнес-волны

Их не обязательно утверждать до пилота. Достаточно проверить, не пропущено ли
важное направление:

- `FP-021`–`FP-026`: рабочее место и контроль менеджеров;
- `FP-030`–`FP-036`: проверки, раздел, аналоги и экономика;
- `FP-040`–`FP-046`: переговоры, покупка, работы, лоты и продажи;
- `FP-050`–`FP-056`: лёгкий кабинет инвестора;
- `FP-060`–`FP-071`: отложенное расширение.

## 5. Вопросы, которые можно оставить открытыми

- облачный провайдер и CI-платформа;
- режим фонового запуска Windows Agent и канал обновлений;
- допустимый способ авторизации на площадке;
- юридические лица, налоги и модель инвесторов;
- точные RPO/RTO и сроки хранения;
- финансовая методика доходности и мультивалютность;
- каналы уведомлений и сообщений продавцам.

Эти вопросы не нужно решать одним заседанием. Каждый имеет обозначенную точку,
когда начинает блокировать реализацию.

## 6. Как оставлять замечания

Достаточно писать: `ID документа → раздел → что изменить`. Не нужно редактировать
формулировки самостоятельно. Если решение неизвестно, пометка `оставить открытым`
сохраняет текущий рекомендуемый вариант без статуса «Принято».

## 7. Результат первого просмотра

- генеральный план и ADR-001–006 уже приняты как направление;
- FP-001–FP-003 и первый сквозной контур: принять или дать конкретный блокер;
- первый рабочий контур: согласованная граница пилота;
- список вопросов к аналитику, юристу и разработчикам;
- разрешение готовить `TP`, но ещё не код, если это соответствует процессу проекта.
