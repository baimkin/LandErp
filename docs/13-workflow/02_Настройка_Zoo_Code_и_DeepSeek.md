# Настройка Zoo Code и DeepSeek для LandErp

## 1. Профиль модели

- Provider: DeepSeek либо совместимый официальный endpoint.
- API key хранится в настройках Zoo Code/защищённом хранилище, не в репозитории.
- Для архитектуры и сложного review выбирать наиболее сильную reasoning/coding
  модель из доступных в текущем API.
- Не закреплять имя быстро меняющейся модели в архитектуре LandErp.

## 2. Разрешения

Принятая политика владельца:

- чтение проектных файлов разрешено;
- запись и изменение файлов — только после подтверждения;
- терминальные команды — только после подтверждения;
- установка пакетов — отдельное подтверждение;
- операции Git — отдельное подтверждение;
- доступ к файлам вне репозитория не предоставляется.

## 3. Режимы Zoo Code

| Режим | Для чего использовать | Может менять код |
|---|---|---|
| Ask | объяснение существующего кода и документов | нет |
| Architect | уточнение FP/TP и оценка вариантов | нет |
| Code | реализация одного утверждённого TP | после подтверждения |
| Debug | воспроизведение и локализация дефекта | после подтверждения |

Orchestrator не использовать для первой волны, пока процесс одного TP не станет
стабильным. Параллельные агенты не должны редактировать одни файлы.

## 4. Контекст задачи

В каждый запрос передавать только:

- утверждённый `TP`;
- связанный `FP`;
- применимые `ADR`;
- нужные разделы генерального плана;
- фактические файлы кода рядом с изменением.

Не прикладывать все 59 планов одновременно. Zoo Code самостоятельно читает
постоянные правила из `.roo/rules/`.

## 5. Контроль расхода и качества

- новую фазу начинать в новой задаче после сохранения handoff;
- просить краткий анализ перед diff, а не многократное переписывание плана;
- не использовать дорогой reasoning для механического форматирования;
- проверять результат компилятором и тестами, а не вторым текстовым обещанием;
- при двух безуспешных попытках остановиться и перейти в Debug с фиксацией фактов.
