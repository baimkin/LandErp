**Результат:** воспроизводимый исследовательский прототип и решение

## Текущий документационный переход

По итогам обсуждения подготовлен отдельный
[TP-LOCAL-001 — локальный сбор Avito/Cian](TP-LOCAL-001_Локальный_сбор_Avito_Cian.md).
Он не переименовывает и не активирует Gate 03–08 ниже. Gate 02 остаётся

TP; последующий scope определяется им после отдельного утверждения владельцем.

## 1. Принцип реализации

Spike строится последовательными Gate. Каждый Gate даёт небольшой проверяемый
результат. Следующий Gate не начинается автоматически, даже если предыдущий
завершён успешно.

Прототип не является production `LandErp.Agent`. Его задача — проверить
критические гипотезы и сформировать повторно используемые контракты, тесты и
правила отказа.

## 2. Целевая структура Spike

```text
LandErp.slnx
global.json
Directory.Build.props
Directory.Packages.props
src/
  LandErp.ParserSpike/
    Application/
    Avito/
    Browser/
    Contracts/
    Diagnostics/
    Serialization/
tests/
  LandErp.ParserSpike.Tests/
fixtures/
  synthetic/
  sanitized/
docs/
```

На старте используется один executable-проект и один тестовый проект. Новые
assembly добавляются только при измеримой необходимости. Папки обозначают
границы ответственности, но не требуют пустых классов.

## 3. Gate

| Gate | Результат | Live Avito | Статус |
|---|---|---:|---|
| 01 | Каркас, контракты, сериализация, минимальные тесты | Нет | Принят владельцем |
| 02 | Windows-прототип с прокруткой, пагинацией и SQLite | 1–10 за сбор, вручную | Реализован локально; ожидает review |
| 03 | Классификация типов страниц | Нет | Не активен |
| 04 | Извлечение основной поисковой выдачи | Нет | Не активен |
| 05 | Извлечение подробной карточки | Нет | Не активен |
| 06 | Headed Playwright и постоянный локальный профиль | Ограниченно | Не активен |
| 07 | Повторяемость, второй Windows-компьютер и метрики | Ограниченно | Не активен |
| 08 | Итоговый отчёт и решение | Нет новых опытов | Не активен |

## 4. Gate 01 — каркас и контракты

Создаются только solution, базовые настройки, executable, тестовый проект,
контрактные типы, сериализация и синтетические unit-тесты. Playwright может быть
зафиксирован в Central Package Management, но браузер не запускается.

Подробный scope находится в `GATE-SPIKE-001-01_Каркас_и_контракты.md`.
Gate принят владельцем 13 сентября 2026 года по коммиту
`8607e8c60f23ea40177ab8742fadc51f867663e3`.

## 5. Gate 02 — fixture harness

Исходный offline scope ниже отложен прямым решением владельца 13 сентября 2026 года.
Вместо него утверждён [первый live-прототип](GATE-SPIKE-001-02_Live_прототип.md):
WPF-окно, Chrome/Edge, отдельный профиль, парсинг только по кнопке и результаты
в таблице. Ранние минимальные классификация/search/browser проверки входят
в новый Gate 02; Gate 03–08 автоматически не активируются.

В последующем обсуждении владелец утвердил расширение того же Gate 02:
постепенная прокрутка, 1–10 страниц, уведомление и ручное продолжение после
проверки, дополнительные поля выдачи, SQLite и просмотр истории для отладки.
Это исключение из прежнего запрета локальной БД/desktop UI; detail extraction,
сервер и последующие Gate остаются вне разрешения. Подробный scope и проверки
зафиксированы в начале документа первого live-прототипа.

- локальный каталог входных файлов;
- проверка размера и типа;
- очищенные fixture metadata;
- отделение synthetic/sanitized/private;
- deterministic fixture runner;
- запрет записи исходного live HTML в Git без sanitization review.

Подробное задание: [GATE-SPIKE-001-02_Fixture_harness.md](GATE-SPIKE-001-02_Fixture_harness.md).
Статус прежнего fixture harness — «Отложен»; не является активным заданием.

## 6. Gate 03 — классификация

- `SearchResults`, `ListingDetails`, `AuthenticationRequired`, `Captcha`,
  `RateLimited`, `ListingUnavailable`, `SourceError`, `Unknown`;
- классификация до извлечения;
- `Unknown` и защитные состояния не возвращают пустой успех;
- негативные fixtures и отчёт причин.

## 7. Gate 04 — выдача

- только основной контейнер;
- external ID и direct URL;
- title, price, area, location, date text и preview metadata;
- отделение рекламы, рекомендаций и других регионов;
- `Raw / Parsed / Presence`;
- completeness и item-level errors.

## 8. Gate 05 — подробная карточка

- параметры, описание, продавец, badges, photo metadata;
- заявленные кадастровые номера как assertion источника;
- противоречащие значения не усредняются;
- отсутствие поля не считается очисткой прошлого значения;
- unavailable относится только к конкретному объявлению.

## 9. Gate 06 — браузер

- headed Chromium;
- отдельный локальный persistent profile;
- ручная авторизация;
- ручная реакция на CAPTCHA с остановкой текущей задачи;
- timeout и наблюдаемое ожидание вместо произвольных задержек;
- ограниченная диагностическая политика;
- отсутствие обходных механизмов.

## 10. Gate 07 — измерение

- повтор нескольких ссылок в разные временные окна;
- проверка на втором Windows-компьютере;
- field-level completeness;
- частота CAPTCHA/auth/rate limit/unknown;
- время навигации и извлечения;
- оценка ручного сопровождения;
- объяснимость каждого сбоя.

## 11. Gate 08 — решение

- итоговая таблица гипотез;
- достигнутые и недостигнутые пороги;
- архитектурные и операционные ограничения;
- review кода, который может быть перенесён;
- решение `Go`, `Conditional Go` или `No-Go`;
- изменения в FP-011–FP-014 и будущие TP.

## 12. Постоянные правила всех Gate

- фиксированные версии пакетов;
- минимальное число зависимостей;
- отсутствие секретов в Git и логах;
- deterministic offline tests;
- structured failure вместо пустого результата;
- одна причина изменения на commit;
- отчёт и остановка после каждого Gate;
- пользователь отдельно утверждает следующий этап.

## 13. Вне TP

- production Server/Worker/Agent;
- PostgreSQL и EF Core;
- Blazor и desktop UI;
- Cian;
- сообщения продавцам;
- телефон продавца;
- обход ограничений источника;
- масштабирование на 30–50 ссылок и 3–5 компьютеров.

## 14. Definition of Done TP

TP закрывается только после Gate 08, когда результат воспроизводим, метрики
собраны и владелец зафиксировал одно из трёх решений. Успешная загрузка одной
страницы не закрывает Spike.
